# C言語の規格と歴史

## 対応C規格

- **主要対象：** C90、C99、C11、C17、C23
- **学習内容：** 各規格の位置づけ、追加機能、規格モードの選び方

## 学習目標

この章を完了すると、次のことができるようになります。

- C89とC90の関係を説明できる
- C99、C11、C17、C23で追加または変更された主な機能を区別できる
- `__STDC_VERSION__`で言語規格の版を確認できる
- 対象処理系と依存ライブラリに合わせて規格モードを選べる

## 標準化までの経緯

C言語は1970年代のはじめに、アメリカのベル研究所で生まれました。
ところが最初のころは、コンピュータやコンパイラ（ソースコードを機械語に翻訳する道具）の種類ごとに、少しずつルールの違いがありました。
まるで地方ごとの方言のように書き方がバラバラだったため、あるパソコンで作ったプログラムを別のパソコンへ持っていくと動かないことがよくあったのです。

そこで、「どのコンピュータでも同じソースコードが動くようにしよう」という目的で、1980年代に共通のルールブック（標準規格）を作る取り組みが進められました。

- **1978年：** Brian Kernighan（ブライアン・カーニハン）とDennis Ritchie（デニス・リッチー）による最初の解説書が出版されました
- **1989年：** アメリカの標準化団体が「ANSI X3.159-1989」を発行しました（通称はC89です）
- **1990年：** 国際標準化団体が「ISO/IEC 9899:1990」を発行しました（通称はC90です）

C89とC90は、技術的な中身がほぼ同じです。
アメリカのルールとして出た年（1989年）で呼ぶか、世界のルールとして出た年（1990年）で呼ぶかの違いだけだと覚えておきましょう。

## 規格の一覧

C言語の規格は、時代に合わせて少しずつ新しくなってきました。
主な規格の一覧は次のとおりです。

| 通称 | 国際規格 | `__STDC_VERSION__` | 主な変更 |
|---|---|---:|---|
| C90 | ISO/IEC 9899:1990 | 定義なし | 初の国際規格 |
| C95 | ISO/IEC 9899:1990/Amd 1:1995 | `199409L` | ワイド文字関連などの追補 |
| C99 | ISO/IEC 9899:1999 | `199901L` | 複合リテラル、指定初期化子、`inline`、`_Bool`など |
| C11 | ISO/IEC 9899:2011 | `201112L` | `_Generic`、原子型、スレッド、静的アサーションなど |
| C17 | ISO/IEC 9899:2018 | `201710L` | C11に対する不具合修正と明確化 |
| C23 | ISO/IEC 9899:2024 | `202311L` | `bool`、`typeof`、`nullptr`、2進整数定数など |

表にある`__STDC_VERSION__`は、コンパイラが自動で用意してくれる「今どのバージョンの規格で動いているか」を示す番号です。
また、C23という呼び名の数字（23）と、国際規格が正式に発行された年（2024年）は一致していません。
C23は2024年にISO/IEC 9899:2024として発行されました。

## C90

C90は、C言語にとって初めての国際標準です。
関数プロトタイプ（関数の名前や引数の型を先に伝えておく宣言）、`void`、`const`、`volatile`、そして標準ライブラリなど、今のC言語の土台となるルールがここで決められました。
今でも、古い機械や長い期間メンテナンスを続けるシステムとの互換性（同じように動く性質）を保つために使われることがあります。

C90では、変数の宣言をブロック（`{`と`}`で囲まれたかたまり）の中で、実行する文よりも先に書く決まりがあります。
関数のいちばん先頭だけでなく、内側に新しく`{ ... }`のブロックを作れば、その先頭でも変数を宣言できます。

```c
int sum_values(void)
{
    int i;
    int sum = 0;

    for (i = 0; i < 10; i++) {
        sum += i;
    }

    return sum;
}
```

このコードでは、`for`文を始める前に`int i;`と`int sum = 0;`をまとめて先頭で宣言しています。
C90では`for (int i = 0; ...)`のようにループの中で変数を宣言できないため、このように書きます。

## C99

C99では、プログラムを書きやすく、安全にするための機能がたくさん追加されました。

- ブロックの途中で変数を宣言できるようになった（宣言と文の混在）
- `for (int i = 0; ...)`のように、`for`文の中でカウンタ変数を宣言できるようになった
- `//`で1行コメントを書けるようになった
- とても大きな整数を扱える`long long`型や、真偽を表す`_Bool`型が追加された
- 関数を高速化しやすくする`inline`、その場で構造体や配列の値を作れる複合リテラル、番号や名前を指定して初期化できる指定初期化子が追加された
- `<stdint.h>`によって、`int32_t`のようにビット幅（大きさ）がきっちり決まった整数型（固定幅整数型）が使えるようになった

```c
#include <stdbool.h>
#include <stdio.h>

int main(void)
{
    bool enabled = true;
    int values[6] = {[0] = 10, [5] = 20};

    for (int i = 0; i < 6; i++) {
        printf("%d\n", values[i]);
    }

    return enabled ? 0 : 1;
}
```

このコードでは、`<stdbool.h>`を使って`bool`や`true`を使っています。
`{[0] = 10, [5] = 20}`が「指定初期化子」で、0番目を`10`、5番目を`20`にし、書いていない残りの要素は自動で`0`になります。
さらに`for`文の中で`int i = 0`と宣言しているのもC99からの書き方です。

また、実行時に大きさを決められる「可変長配列（VLA）」もC99で追加されました。
ただしC11以降では、関数内の通常の可変長配列に対応しないコンパイラもあるため、使うときは規格のバージョンだけでなく、自分のコンパイラが対応しているかも確認します。

## C11

C11では、より安全にプログラムをチェックする機能や、複数の処理を同時に進めるための機能が追加されました。

- **`_Generic`：** 渡された値の型に合わせて、使う式や関数を自動で切り替える仕組み
- **`_Static_assert`：** プログラムを実行する前（コンパイル時）に「この条件が成り立っているか」をチェックする仕組み
- **アラインメント指定：** データをメモリ上のキリのよい場所に並べるための指定
- **原子型・スレッドライブラリ：** 複数の作業を同時に動かす（マルチスレッド）ときに、データが壊れないように安全に扱うための仕組み
- **匿名構造体・共用体：** 名前をつけずに構造体や共用体の中に埋め込める仕組み

```c
#include <limits.h>

_Static_assert(sizeof(int) * CHAR_BIT >= 16,
               "int must occupy at least 16 bits");

#define TYPE_NAME(x) _Generic((x), \
    int: "int", \
    float: "float", \
    double: "double", \
    default: "other")
```

上の`_Static_assert`は、「`int`型が16ビット以上あること」をコンパイル時に確かめています。
もし条件を満たさない環境なら、その場でエラーメッセージを出して止めてくれます。
下の`TYPE_NAME(x)`は、渡した変数`x`の型に応じて`"int"`や`"double"`といった文字列を選んでくれます。

なお、スレッドや原子操作などの一部の機能は、すべてのコンパイラに必須ではなく「任意機能」になっています。
対応していない環境では、それを知らせるための機能テストマクロが定義されます。
たとえば、`__STDC_NO_THREADS__`が定義されている環境では、`<threads.h>`は使えません。

## C17

C17は、C11で見つかった細かい不具合の修正や、ルールブックのわかりにくい表現をはっきりさせることを目的とした規格です。
新しい言語機能は追加されていません。
そのため、C11の機能を使うプログラムを書くときも、コンパイラが対応していれば修正版であるC17モードを選んでおくと安心です。

## C23

C23では、今の時代に合わせた書きやすさと安全性を高める新機能が多く加わりました。
`bool`、`true`、`false`、`static_assert`などが最初から使えるキーワードになっています。
ほかにも、`typeof`、`typeof_unqual`、`nullptr`、好きなビット幅の整数を作れる`_BitInt`、2進整数定数、数字の桁区切り、ファイルをデータとして埋め込む`#embed`、`auto`による型推論、`constexpr`オブジェクトなどが追加されました。

```c
bool ready = true;
auto count = 42;
typeof(count) next_count = count + 1;
int *pointer = nullptr;
unsigned int mask = 0b1111'0000U;
```

ヘッダーファイルを読み込まなくても`bool`や`true`が使え、`0b1111'0000U`のように2進数を見やすく区切って書けています。
C23の詳しい使い方は、[C23の新機能](../c23-features/README.md)で学べます。

## 規格版をプログラムから確認する

C95以降の規格に準拠した処理系では、`__STDC_VERSION__`というマクロにバージョン番号が入ります。
ただし、C90モードではこのマクロ自体が定義されないため、最初に`defined`を使って「定義されているかどうか」を確認するのがポイントです。

```c
#if !defined(__STDC_VERSION__)
/* C90 or a non-conforming mode */
#elif __STDC_VERSION__ >= 202311L
/* C23 or later */
#elif __STDC_VERSION__ >= 201710L
/* C17 */
#elif __STDC_VERSION__ >= 201112L
/* C11 */
#elif __STDC_VERSION__ >= 199901L
/* C99 */
#endif
```

このように上から新しい順に比べることで、今どの規格モードでコンパイルされているかを判定できます。

ただし、`__STDC_VERSION__`でわかるのは規格のバージョン番号だけです。
スレッドなどの任意機能が使えるかどうかや、コンパイラ独自の拡張機能があるかまではわかりません。
実際に使うときは、必要なヘッダーファイルがあるか、機能テストマクロがどうなっているか、そして警告付きでコンパイルが通るかも確認します。

## 規格モードを選ぶ基準

「新しい規格だから必ずこれを使う」「古い規格の方がいつも良い」と決めつけるのではなく、作るプログラムの条件（制約）に合わせて規格モードを選びます。

1. **対象処理系：** 使う予定のすべてのコンパイラが、どの規格に対応しているか確認します
2. **依存関係：** 借りて使うライブラリやSDK（開発キット）が、どの規格を必要としているか確認します
3. **公開インターフェース：** 自分の作ったヘッダーファイルを他の人が使う場合、相手側のコンパイラでも読み込める書き方を選びます
4. **必要な機能：** `_Generic`や`nullptr`など、プログラムに本当に必要な機能があるか整理します
5. **検証方法：** CI（コードを自動でテストする仕組み）とコンパイラの警告オプションを使い、選んだ規格のルールを守れているか継続してチェックします

古い規格ほど必ずどこでも動くとは限りませんし、新しい規格ほど自動的に安全になるわけでもありません。
コードの書き方の丁寧さ、使う機能、動かす環境の組み合わせで決まります。

## コンパイラで規格モードを指定する

GCCやClangといった代表的なコンパイラでは、`-std=`オプションを使って規格モードを指定できます。

```bash
gcc -std=c90 -Wall -Wextra -pedantic program.c
gcc -std=c99 -Wall -Wextra -pedantic program.c
gcc -std=c11 -Wall -Wextra -pedantic program.c
gcc -std=c17 -Wall -Wextra -pedantic program.c
gcc -std=c23 -Wall -Wextra -pedantic program.c
```

後ろについている`-Wall -Wextra -pedantic`は、「怪しい書き方や規格から外れた書き方があったら教えてね」という警告オプションです。

C23への移行期に作られたコンパイラでは、`-std=c23`の代わりに`-std=c2x`という名前を使うことがあります。
自分が使っているコンパイラでどんなオプションが使えるかは、コンパイラのヘルプ（`gcc --help`など）で確認しましょう。
