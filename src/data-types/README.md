# 第3章：データ型と変数

## 対応するC規格

- **主要対象**：C90
- **学習内容**：基本型、宣言、初期化、型変換、スコープ、記憶域期間、`const`、`sizeof`

## 学習目標

この章では、データを入れる箱の種類（型）と、変数が「どこで使えて、いつまで生きているか」というルールを学びます。

- 基本型の性質と、環境によって変わりうる値の範囲を区別できる
- 変数を宣言し、値を読む前に正しく初期化できる
- 自動で行われる型変換（暗黙の型変換）で値がどう変わるか説明できる
- スコープ、リンケージ、記憶域期間の違いを区別できる
- `sizeof`の結果を正しい型で扱える

## オブジェクトと型

C言語では、メモリ（番号つきのロッカーのような場所）の中に確保された「値を入れておく箱そのもの」を**オブジェクト**と呼びます。
そして、その箱に名前（**識別子**）をつけてプログラムから使えるようにしたものが**変数**です。

変数を作るときは、「どんな種類のデータを入れる箱か（**型**）」と「名前」をセットで書きます。
これを**宣言**といいます。

```c
int count;
double average;
char grade;
```

上の例では、整数用の箱`count`、小数用の箱`average`、1文字用の箱`grade`をそれぞれ用意しています。

**型**は、その箱で「値をどう表すか」「どんな計算ができるか」「メモリをどれくらい使うか」を決めるルールです。
コンピューターの内部ではすべてのデータが0と1の並び（ビット列）で保存されていますが、型が違えば、同じ0と1の並びでも「文字」として解釈されたり「数字」として解釈されたりします。

## 整数型

小数点がつかない数を扱うのが**整数型**です。
標準Cの基本整数型には、小さい順の目安として`char`、`short`、`int`、`long`があり、それぞれに**符号付き**（マイナスもプラスも表せる`signed`）と**符号なし**（0以上の数だけを表す`unsigned`）があります。

ただし、`char`型だけは少し特別で、`signed char`と同じ範囲になるか`unsigned char`と同じ範囲になるかは、使うコンパイラやパソコンの組み合わせ（処理系）が決めます。
このような「処理系が決めてよいルール」を**処理系定義**と呼びます。

整数型の大きさ（ビット幅）は、C言語のルールでは固定されていません。
標準Cが保証しているのは、それぞれの型が最低限必要な範囲を表せることと、次の大きさの順番を守ることだけです。

```text
sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long)
```

ここで`sizeof(char)`は常に`1`（1バイト）ですが、C言語における1バイトが必ずしも8ビット（0か1のマスが8個分）とは限りません。
使っている環境で1バイトが何ビットかは、`<limits.h>`というヘッダファイルにある`CHAR_BIT`で確認できます。

また、各整数型に入れられる最小値や最大値は、`<limits.h>`の`INT_MIN`、`INT_MAX`、`UINT_MAX`などで調べられます。
「ちょうど32ビットの整数を使いたい」というように正確なビット幅が必要な場合は、C99以降で追加された`<stdint.h>`の`int32_t`などを検討します。
ただし、これらの正確な幅の型は、その環境がちょうどそのビット幅に対応している場合にだけ用意されます。

### 整数型の選択

ふだんの整数計算には、基本的に`int`を使います。
スイッチのON/OFFをまとめて管理する処理（ビット集合）や、時計の針のように最大値を超えたら0へ戻る計算（剰余算術）には、符号なし整数型（`unsigned`）が向いています。

ただし、「マイナスの数は使わないから」という理由だけで`unsigned`を選ぶのは避けたほうが安全です。
符号付きの整数と符号なしの整数を比べたとき、マイナスの数が予期せず巨大なプラスの数へ変換されてしまうことがあるためです。

文字データを入れるときは`char`を使います。
画像ファイルの中身のような生のバイト列や、0から`UCHAR_MAX`までの数値をそのまま扱いたいときは、`unsigned char`を使います。

## 浮動小数点型

小数点がつく数を扱うのが**浮動小数点型**です。
標準Cには、`float`、`double`、`long double`の3種類があり、この順に表せる細かさ（精度）と範囲が狭くならないことが保証されています。
ふつうの小数の計算では、精度と扱いやすさのバランスがよい`double`がよく使われます。
ただし、各型が何バイト使うかや、国際標準であるIEEE 754という方式に完全に従うかどうかは、標準Cでは強制されていません。

実際の精度や最大値は、`<float.h>`の`FLT_DIG`、`DBL_DIG`、`FLT_MAX`、`DBL_MAX`などで確認できます。

小数を扱うときに大切なのが**丸め誤差**です。
私たちがふだん使う10進数の`0.1`のような小数でも、コンピューターが使う2進数では割り切れず、`0.333...`のようにわずかなズレが出ます。
そのため、お金の金額など1円のズレも許されない値では、小数ではなく「1円単位」などの最小単位の整数で保持する方法が適しています。

## 宣言と初期化

変数の箱を作ったら、中身を読み取る前に必ず最初の値を入れておきます。
宣言と同時に最初の値を入れることを**初期化**といいます。

```c
int count = 0;
double ratio = 0.5;
char grade = 'A';
```

C90のルールでは、`{`と`}`で囲まれたブロック（複合文）ごとに、処理の文より前に変数の宣言をまとめて書きます。
「関数の先頭だけ」ではなく、`if`文などの内側のブロックの先頭にも宣言を置けます。

```c
int main(void)
{
    int value = 10;

    if (value > 0) {
        int doubled = value * 2;
        value = doubled;
    }

    return 0;
}
```

ブロックの中で宣言した通常の変数（自動記憶域期間を持つオブジェクト）は、初期化しないと中身が何になるかわからない**不定値**（前に使われていたゴミのようなデータ）になります。
不定値を読み取ると、型や状況によっては未定義動作（ルール違反）になるため、初期化していない変数を`printf`で表示して「どんな値が出るか見てみよう」とする実験は行いません。

## 代入と算術

**代入演算子**`=`は、右側の値を左側の変数の型へ合わせてから箱の中へ入れます。
`+=`や`-=`のように、計算と代入を1つにまとめた書き方（複合代入）もよく使われます。

```c
int number = 10;

number += 5;
number -= 3;
number *= 2;
number /= 4;
```

上の例では、`number`の中身は最初に`10`で、そこから`+5`で`15`、`-3`で`12`、`*2`で`24`、`/4`で`6`へと順に変わります。

整数どうしの割り算（整数除算）では、小数点以下は切り捨てられて整数になります。
C99以降では小数部を0の方向へ切り捨てる決まりですが、C90ではマイナスの数を含む割り算やあまりの丸め方向が処理系定義でした。

```c
int a = 5;
int b = 2;
int quotient = a / b;              /* 2 */
double average = (double)a / b;    /* 2.5 */
```

`a / b`は整数どうしなので`2`になります。
小数の`2.5`を得たいときは、`(double)a`のように片方を小数へ変換してから割ります。

なお、`0`で割る整数除算やあまり（剰余）の計算は未定義動作です。
割る数がユーザーからの入力などで決まる場合は、計算する前に必ず`0`でないか確認します。

## 型変換

代入や関数呼び出し、計算式などでは、必要に応じて値が別の型へ自動的に変換されます（暗黙の型変換）。
また、プログラマーが「この型へ変換してほしい」と明示的に書く構文を**キャスト**と呼びます。

```c
int total = 100;
int count = 3;
double average = (double)total / count;
```

ここでは`(double)total`とキャストすることで、`total`を`double`型の`100.0`として扱い、`100.0 / 3`の小数計算を行っています。

整数型と浮動小数点型の変換ルールは、「小さい型から大きい型へ広がる」という単純な順位だけでは説明できません。
整数拡張（小さい整数型が`int`などへ広がる仕組み）、整数変換の順位、符号の有無、それぞれの型が表せる範囲を組み合わせて決まります。

### 値が範囲外になる変換

ある型の値を別の型へ変換したとき、変換先の箱に入りきらないことがあります。
そのときの動きは、変換先が「符号なし」か「符号付き」かで大きく異なります。

符号なし整数型への変換では、時計の針が一周して戻るように、その型が表せる値の個数で割ったあまり（法とする算術）になります。

```c
unsigned int wrapped = (unsigned int)-1;
```

この例では、`-1`が符号なし整数型へ変換され、その型の最大値（`UINT_MAX`）になります。

一方、符号付き整数型への変換で値が範囲外になった場合、結果は処理系定義になるか、異常を知らせるシグナルが発生します。
「必ず-1になるはず」など、特定の結果を決めつけてはいけません。

浮動小数点型から整数型へ変換すると、小数点以下は0の方向へ切り捨てられます。
切り捨てたあとの整数が変換先の型に収まらない場合は、未定義動作になります。

計算そのものが範囲を超えた場合（オーバーフロー）も同じように注意が必要です。
符号付き整数の計算結果が型の範囲を超えると未定義動作になりますが、符号なし整数の計算は最大値に1を足した数を法として一周する仕組み（モジュロ算術）として定義されています。

## スコープ、リンケージ、記憶域期間

変数を正しく扱うには、次の3つの概念を区別して理解することが大切です。

- **スコープ**：その変数の名前を使える「有効範囲」のことです（教室の中だけで通じる名前か、学校全体で通じる名前かのような違いです）。
- **リンケージ**：別の場所に書いた同じ名前が「同じ1つの箱」を指すか、「別の箱」を指すかを決めるつながりです。
- **記憶域期間**：その箱がメモリ上に存在している「寿命」のことです（いつ作られて、いつ消えるかを決めます）。

### ファイルスコープとブロックスコープ

関数の外側で宣言した名前は、宣言した場所からそのファイル（翻訳単位）の最後まで使える**ファイルスコープ**を持ちます。
一方、関数の中や`if`文の`{`と`}`の中で宣言した変数は、そのブロックの中だけで使える**ブロックスコープ**を持ちます。

```c
static int file_private = 100;

int get_value(void)
{
    int local = file_private;
    return local;
}
```

この例では、`file_private`はファイルスコープ、`local`は`get_value`関数の中だけで使えるブロックスコープを持っています。

細かい用語の注意点として、C言語で「関数スコープ」を持つのは`goto`文で使うラベルだけです。
関数の中で宣言したふつうの変数を「関数スコープ」と呼ぶのは正確ではありません。

また、`file_private`のようにファイルスコープの変数へ`static`をつけると、**内部リンケージ**を持ちます。
これは「このファイルの中だけで秘密に使い、ほかのファイルからは同じ名前で見えないようにする」という意味です。

### 自動記憶域期間

ブロックの中で宣言したふつうの変数は、**自動記憶域期間**を持ちます。
プログラムがそのブロックへ入るたびに箱が作られ、ブロックから出ると自動的に片づけられて寿命が終わります。
解説書などでは「スタックという領域に置かれる」と説明されることがありますが、標準Cの規格自体は「必ずスタックへ置くこと」とは規定していません。

```c
void count_once(void)
{
    int count = 0;
    count++;
}
```

この`count`は、`count_once`関数が呼ばれるたびに新しく`0`で作られ、関数が終わると消えます。

### 静的記憶域期間

ファイルスコープの変数と、ブロックの中で`static`をつけて宣言した変数は、**静的記憶域期間**を持ちます。
これらの箱はプログラムが始まる前に用意され、プログラムが終わるまでずっとメモリ上で値を保ち続けます。
最初の値を書き忘れた場合でも不定値にはならず、型に応じて自動的に`0`（またはヌルポインター）で初期化されます。

```c
int next_id(void)
{
    static int id;
    return ++id;
}
```

この`id`は`static`がついているため、最初に`0`で初期化され、関数が終わっても中身が消えません。
そのため、`next_id()`を呼ぶたびに`1`、`2`、`3`と1つずつ増えた番号を返します。

### `register`指定子

変数の宣言に`register`をつけると、「よく使うので速くアクセスできる場所（CPUレジスタ）へ置いてほしい」というヒントになります。
ただし、`register`をつけた変数にはメモリの場所を調べる単項`&`演算子を使えません。
また、実際にCPUレジスタへ置かれる保証はなく、どこに置くかはコンパイラが判断します。

## `const`修飾子

型に`const`をつけると、その名前（左辺値）を通して箱の中身を書き換えることができなくなります。
うっかり値を変えてほしくない定数や、読み取るだけの文字列に役立ちます。

```c
const int max_count = 100;
const char *text = "Hello";
```

ただし、C90のルールでは、ブロックの中で宣言した`const int`はコンパイル時に決まる「整数定数式」とはみなされません。
そのため、固定長配列の要素数（箱の個数）には使えません。
C90で配列のサイズに名前をつけたいときは、列挙定数（`enum`）や、整数定数式になるマクロを使います。

```c
enum { BUFFER_SIZE = 64 };
char buffer[BUFFER_SIZE];
```

**マクロ**（`#define`）は、コンパイルの前にプリプロセッサという下準備の仕組みが文字をそのまま置き換える機能で、型を持ちません。
計算式のようなマクロを作るときは、優先順位が崩れないように引数と全体を括弧で囲む必要があります。
さらに、引数が式の中に複数回出てくると、その回数だけ評価されてしまう点にも注意が必要です。

```c
#define SQUARE(x) ((x) * (x))
```

たとえば`SQUARE(i++)`と書くと`((i++) * (i++))`へ置き換わり、1つの式の中で同じ変数`i`を2回も更新してしまうため使ってはいけません。

## `sizeof`演算子

`sizeof`は、型や変数がメモリ上で何バイトの大きさを使っているかを調べる演算子です。
結果は、大きさを表すための符号なし整数型である`size_t`型で返ります。
型名を調べるときは括弧が必要ですが、変数や式を調べるときは括弧を省略できます。

```c
sizeof(int)
sizeof value
sizeof(value)
```

`size_t`型の値を`printf`で表示する指定子`%zu`は、C99で追加されました。
C90では`%zu`が使えないため、値が`unsigned long`型に収まることを確認したうえで`(unsigned long)`へキャストし、`%lu`で表示します。

```c
printf("int: %lu bytes\n", (unsigned long)sizeof(int));
```

ふつう、`sizeof`の後ろに書いた式は型を調べるだけで、実際に実行（評価）されることはありません。
ただし、C99以降で追加された「実行時に長さが決まる配列（可変長配列）」の大きさを調べるときだけは、実行時に式が評価されます。
そのため、「`sizeof`の中身は絶対に実行されない」と決めつけてはいけません。

配列の要素数（箱が何個並んでいるか）は、配列そのものが見えている場所なら「全体のバイト数 ÷ 1個分のバイト数」で求められます。

```c
int values[10];
size_t count = sizeof values / sizeof values[0];
```

ただし、この計算を関数の仮引数（受け取った配列）に対して行うと、配列がポインター型へ自動的に変わってしまうため、正しい要素数は得られません。

## コンパイル

```bash
gcc -std=c90 -Wall -Wextra -pedantic examples/basic_types.c -o basic_types
./basic_types
```

`Makefile`を使う場合は、次のコマンドを実行します。

```bash
make all
make run-all
make clean
```

## C99で追加された主な機能

C99では、さらに大きい整数を扱う`long long`、真か偽かを表す`_Bool`、複素数型、文の途中での変数宣言、可変長配列などが追加されました。
なお、C11やC17では可変長配列への対応が「処理系ごとの任意機能」になったため、使う規格とコンパイラで対応しているか確認することが大切です。
