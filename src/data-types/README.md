# 第3章：データ型と変数

## 対応するC規格

- **主要対象**：C90
- **学習内容**：基本型、宣言、初期化、型変換、スコープ、記憶域期間、`const`、`sizeof`

## 学習目標

この章では、値を表現する型と、変数を利用できる範囲・期間を学びます。

- 基本型の性質と処理系依存の範囲を区別できる
- 変数を宣言し、使用前に初期化できる
- 暗黙の型変換による値の変化を説明できる
- スコープ、リンケージ、記憶域期間を区別できる
- `sizeof`の結果を正しい型で扱える

## オブジェクトと型

Cの**オブジェクト**は、値を格納する記憶領域です。
変数の宣言では、オブジェクトの型と識別子を指定します。

```c
int count;
double average;
char grade;
```

型は、値の表現、演算の規則、必要な記憶領域を決めます。
同じビット列でも、型が異なれば解釈や演算結果が異なる場合があります。

## 整数型

標準Cの基本整数型には、`char`、`short`、`int`、`long`と、それぞれの符号付き・符号なしの型があります。
ただし、`char`が`unsigned char`と同じ範囲か`signed char`と同じ範囲かは処理系定義です。

型の幅は固定されていません。
標準が保証するのは、各型が少なくとも必要な範囲を表現でき、次の大小関係を満たすことです。

```text
sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long)
```

`sizeof(char)`は常に1ですが、Cにおける1バイトが必ず8ビットとは限りません。
1バイトのビット数は、`<limits.h>`の`CHAR_BIT`で確認できます。

各処理系における範囲は、`<limits.h>`の`INT_MIN`、`INT_MAX`、`UINT_MAX`などで確認します。
特定のビット幅が必要な場合は、C99以降の`<stdint.h>`が提供する`int32_t`などを検討します。
これらの正確な幅の型は、処理系が対応する表現を持つ場合にだけ定義されます。

### 整数型の選択

通常の整数計算には`int`を使います。
ビット集合や剰余算術には、符号なし整数型が適します。
ただし、「負の値を使わない」という理由だけで`unsigned`を選ぶべきではありません。
符号付き整数との比較で、意図しない型変換が起こることがあるためです。

文字データの格納には`char`を使います。
生のバイト列や0から`UCHAR_MAX`までの値を扱う場合は、`unsigned char`を使います。

## 浮動小数点型

標準Cの浮動小数点型は、`float`、`double`、`long double`の3種類です。
この順に精度と表現範囲が狭くならないことは保証されます。
ただし、各型のバイト数やIEEE 754への準拠は、標準Cでは規定されません。

実際の精度と範囲は、`<float.h>`が定義する`FLT_DIG`、`DBL_DIG`、`FLT_MAX`、`DBL_MAX`などで確認できます。
多くの10進小数は二進の浮動小数点数で正確に表せないため、計算では丸め誤差を考慮します。
金額など10進単位を厳密に扱う値は、最小通貨単位に換算して整数で保持する方法が適しています。

## 宣言と初期化

変数は、最初に読み取る前に値を設定します。

```c
int count = 0;
double ratio = 0.5;
char grade = 'A';
```

C90では、各複合文の宣言を、その複合文に含まれる文より前へ置きます。
「関数の先頭だけ」でなく、内側のブロックの先頭にも宣言できます。

```c
int main(void)
{
    int value = 10;

    if (value > 0) {
        int doubled = value * 2;
        value = doubled;
    }

    return 0;
}
```

初期化していない自動記憶域期間のオブジェクトは、不定値を持ちます。
不定値の読み取りは、型や状況によって未定義動作になり得るため、表示して「どの値になるか」を観察する教材にはしません。

## 代入と算術

代入演算子は、右辺を左辺の型へ変換して格納します。

```c
int number = 10;

number += 5;
number -= 3;
number *= 2;
number /= 4;
```

C99以降の整数除算では、小数部を0方向へ切り捨てます。
C90では、負のオペランドを含む除算と剰余の丸め方向が処理系定義です。

```c
int a = 5;
int b = 2;
int quotient = a / b;              /* 2 */
double average = (double)a / b;    /* 2.5 */
```

0による整数除算と剰余は未定義動作です。
除数が入力値で決まる場合は、演算前に0でないことを確認します。

## 型変換

代入、関数呼び出し、算術式などでは、必要に応じて値が別の型へ変換されます。
変換を明示する構文がキャストです。

```c
int total = 100;
int count = 3;
double average = (double)total / count;
```

整数型と浮動小数点型の変換規則は、単純な「小さい型から大きい型への順位」では説明できません。
整数拡張、整数変換の順位、符号の有無、各型が表現できる範囲に基づいて決まります。

### 値が範囲外になる変換

符号なし整数型への変換結果は、その型が表現できる値の個数を法として繰り返し加減した値です。

```c
unsigned int wrapped = (unsigned int)-1;
```

符号付き整数型への変換で値を表現できない場合、結果は処理系定義になるか、処理系定義のシグナルが発生します。
「常に-1になる」など、特定の結果を前提にしてはいけません。

浮動小数点型から整数型への変換では、小数部が0方向へ切り捨てられます。
切り捨て後の値を変換先の整数型で表現できない場合、動作は未定義です。

符号付き整数演算で結果を型の範囲内に表現できない場合も、動作は未定義です。
一方、符号なし整数演算は、その型の最大値に1を加えた数を法とする算術です。

## スコープ、リンケージ、記憶域期間

**スコープ**は、識別子を名前で参照できる範囲です。
**リンケージ**は、別の宣言が同じ実体を指すかどうかを決めます。
**記憶域期間**は、オブジェクトの生存期間です。

### ファイルスコープとブロックスコープ

関数の外側で宣言した識別子は、宣言位置から翻訳単位の末尾までファイルスコープを持ちます。
関数本体や`if`文のブロック内で宣言した変数は、ブロックスコープを持ちます。

```c
static int file_private = 100;

int get_value(void)
{
    int local = file_private;
    return local;
}
```

Cで関数スコープを持つのはラベルです。
関数内で宣言した通常の変数を「関数スコープ」と呼ぶのは正確ではありません。

ファイルスコープのオブジェクトへ`static`を指定すると、内部リンケージを持ち、同じ翻訳単位の外部から同じ識別子で参照できなくなります。

### 自動記憶域期間

通常のブロック内変数は、自動記憶域期間を持ちます。
宣言を含むブロックへ入るたびに生存期間が始まり、ブロックから出ると終了します。
標準Cは、このオブジェクトが「スタック」に置かれるとは規定していません。

```c
void count_once(void)
{
    int count = 0;
    count++;
}
```

### 静的記憶域期間

ファイルスコープのオブジェクトと、`static`を指定したブロック内オブジェクトは、静的記憶域期間を持ちます。
プログラムの開始前に初期化され、実行中は値を保持します。
明示的な初期化子がない場合は、型に応じた0またはヌルポインタへ初期化されます。

```c
int next_id(void)
{
    static int id;
    return ++id;
}
```

### `register`指定子

`register`を指定したオブジェクトには、単項`&`演算子を適用できません。
処理系がCPUレジスタへ格納する保証はなく、格納場所は実装が決めます。

## `const`修飾子

`const`で修飾した型の左辺値を通じて、オブジェクトを変更することはできません。

```c
const int max_count = 100;
const char *text = "Hello";
```

C90では、ブロックスコープの`const int`は整数定数式ではないため、固定長配列の要素数には使えません。
固定長配列の上限には、列挙定数や整数定数式になるマクロを使用できます。

```c
enum { BUFFER_SIZE = 64 };
char buffer[BUFFER_SIZE];
```

マクロはプリプロセス時のトークン置換であり、型を持ちません。
式形式のマクロでは、引数と展開全体を括弧で囲み、副作用を持つ引数が複数回評価される点に注意します。

```c
#define SQUARE(x) ((x) * (x))
```

`SQUARE(i++)`のような呼び出しは、同じオブジェクトを複数回更新するため使用しません。

## `sizeof`演算子

`sizeof`は、型または式の型が占めるバイト数を`size_t`型で返します。
型名には括弧が必要ですが、式の括弧は任意です。

```c
sizeof(int)
sizeof value
sizeof(value)
```

`size_t`の値を`printf`で表示する`%zu`はC99で追加されました。
C90では、表示可能な範囲であることを確認したうえで`unsigned long`へ変換し、`%lu`を使用します。

```c
printf("int: %lu bytes\n", (unsigned long)sizeof(int));
```

通常、`sizeof`のオペランドの式は評価されません。
ただし、C99以降の可変長配列型の大きさを決める必要がある場合は、実行時に評価されます。
したがって、「`sizeof`のオペランドには常に副作用がない」と一般化してはいけません。

配列の要素数は、配列そのものが見える場所で次のように求められます。

```c
int values[10];
size_t count = sizeof values / sizeof values[0];
```

この式を関数仮引数に対して使うと、仮引数の配列宣言がポインタ型へ調整されるため、要素数は得られません。

## コンパイル

```bash
gcc -std=c90 -Wall -Wextra -pedantic examples/basic_types.c -o basic_types
./basic_types
```

Makefileを使う場合は、次のコマンドを実行します。

```bash
make all
make run-all
make clean
```

## C99で追加された主な機能

C99では、`long long`、`_Bool`、複素数型、文の後での宣言、可変長配列などが追加されました。
C11とC17では可変長配列への対応が処理系の任意機能であるため、対象とする規格と処理系で利用可能かを確認します。
