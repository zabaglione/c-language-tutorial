# C23の新機能

## 対応C規格

- **主要対象：** C23
- **学習内容：** `bool`、`typeof`、`nullptr`、2進整数定数、桁区切り、型推論、`constexpr`

## 学習目標

この章を完了すると、次のことができるようになります。

- C23の規格バージョンを機能テストマクロで判定できる
- `bool`、`true`、`false`をキーワードとして使用できる
- `typeof`と`typeof_unqual`の違いを説明できる
- `nullptr`と整数定数`0`の違いを説明できる
- 2進整数定数と桁区切りを正しい構文で記述できる
- 利用する処理系が各機能を実装しているか確認できる

## C23の位置づけ

C言語には、世界中のプログラマーが同じルールで書けるように決められた「規格（ルールブック）」があります。
C23は、その中でも新しいC言語規格の通称です。
正式な国際規格としては「ISO/IEC 9899:2024」という名前で2024年に発行されました。

C23に対応した処理系（コンパイラなどの開発ツール一式）でコンパイルすると、`__STDC_VERSION__`という特別な目印（マクロ）に`202311L`という番号が入ります。
この番号を調べれば、今使っているコンパイラがC23モードで動いているかどうかを確認できます。

```c
#if defined(__STDC_VERSION__) && __STDC_VERSION__ >= 202311L
/* C23 mode */
#else
#error "C23 or later is required"
#endif
```

このコードでは、`__STDC_VERSION__`が定義されていて、しかも`202311L`以上ならC23モードとして先に進みます。
もし条件に合わなければ、`#error`によって「C23以降が必要です」というエラーを出してコンパイルを止めます。

ただし、コンパイラにC23モードを指定しても、すべての新機能がすでに実装されているとは限りません。
新しい機能を使うときは、コンパイル時のメッセージ（警告やエラー）と、コンパイラの公式リリースノート（更新情報）をいっしょに確認しましょう。

## `bool`、`true`、`false`

プログラムでは、「準備ができているか」「条件に合っているか」といった「はい（真）・いいえ（偽）」の状態をよく扱います。
C99では`_Bool`という型が追加され、`<stdbool.h>`というヘッダーファイルを読み込むことで、`bool`、`true`、`false`というわかりやすい名前をマクロとして使えるようになりました。

C23では、`bool`、`true`、`false`が最初からC言語の正式なキーワード（予約された言葉）になりました。
そのため、これらを使うためだけに`<stdbool.h>`を`#include`する必要はありません。

```c
bool is_ready = false;

if (!is_ready) {
    is_ready = true;
}
```

この例では、最初に`is_ready`という箱に`false`（まだ準備ができていない）を入れています。
次の`if`文で「準備ができていなければ（`!is_ready`）」、`true`（準備完了）に書き換えています。

`bool`型に変換した値は、`0`なら`false`、`0`以外の数ならすべて`true`になります。
なお、`bool`は「はい・いいえ」の状態をしまっておくための型であり、入力された値が正しいかどうかや、処理が成功したかどうかを自動でチェックしてくれるわけではありません。

### 以前の規格との比較

古い規格と比べると、C23では書く手間が減ってすっきりしていることがわかります。

```c
/* C90 */
int is_ready = 0;

/* C99以降 */
#include <stdbool.h>
bool is_ready = false;

/* C23 */
bool is_ready = false;
```

C90のころは`bool`型がなかったので、`int`型を使って`0`を「いいえ」、`1`などを「はい」として表現していました。

## `typeof`と`typeof_unqual`

`typeof`は、すでに書かれている変数や式、または型名から「その型」を取り出す演算子です。
たとえば、「変数`count`とまったく同じ型の新しい変数を作りたい」というときに使えます。
以前からGCCなどのコンパイラが独自機能として用意していた仕組みが、C23で正式な標準機能になりました。

```c
int count = 10;
typeof(count) next_count = count + 1;

double price = 19.99;
typeof(price) tax = 1.10;
```

`typeof(count)`は`count`の型である`int`になるので、`next_count`は`int`型になります。
同じように、`typeof(price)`は`double`型になるため、`tax`も`double`型として宣言されます。

ここで、`typeof`と`typeof_unqual`の違いを押さえておきましょう。
変数には、`const`（あとから書き換え禁止にするシール）のような「修飾子」がついていることがあります。

- **`typeof`：** 元の型についている修飾子（`const`など）や原子型（`_Atomic`）の性質をそのまま引き継ぎます
- **`typeof_unqual`：** 元の型から`const`、`volatile`、`restrict`、`_Atomic`といった修飾子を取り除いた型を作ります

```c
const int limit = 100;
typeof(limit) same_limit_type = 50;          /* const int */
typeof_unqual(limit) mutable_limit = 50;     /* int */
```

この例では、`limit`に`const`（書き換え禁止）がついています。
`typeof(limit)`で作った`same_limit_type`も書き換え禁止の`const int`になりますが、`typeof_unqual(limit)`で作った`mutable_limit`は`const`が外れて普通の`int`になるため、あとから値を変えられます。

また、配列に対して`typeof`を使うと、先頭要素へのポインターには変換されず、そのまま配列の型を取り出せます。

```c
int values[4] = {1, 2, 3, 4};
typeof(values) copy = {5, 6, 7, 8};  /* int[4] */
```

`values`は「`int`が4個並んだ配列（`int[4]`）」なので、`copy`も同じ大きさの配列として作られます。

## `nullptr`

ポインターは「メモリの場所（アドレス）を書いておくメモ」のようなものですが、「まだどこも指していないよ」と表したいことがあります。
C23で追加された`nullptr`は、その「空っぽのポインター」を専用に表す定数です。

`nullptr`の型は`nullptr_t`（`<stddef.h>`で定義）といいます。
オブジェクトを指すポインター型、関数ポインター型、そして`bool`型へ変換できます。

```c
#include <stddef.h>

int *data = nullptr;
nullptr_t no_address = nullptr;

if (data == nullptr) {
    /* data does not point to an object */
}
```

このコードでは、`data`を`nullptr`で初期化し、`if`文で「どこも指していないか」を確かめています。

これまで使われてきた整数定数の`0`や`NULL`も、C23で引き続き使えます。
では、なぜ新しく`nullptr`が用意されたのでしょうか。
それは、`nullptr`が整数としては使えないため、「これは数字の0ではなく、ポインター専用の空っぽの値だ」とコンパイラが型でしっかり区別できるからです。

```c
int *pointer_value = nullptr;  /* valid */
bool flag = nullptr;           /* false */
/* int integer_value = nullptr; */  /* constraint violation */
```

ポインター変数には代入でき、`bool`型にすると`false`になりますが、`int`型の変数に入れようとするとエラー（制約違反）になります。
うっかりポインター用の値を数字として使ってしまうミスを防げるのが利点です。

なお、C++という別の言語には「同じ名前の関数を引数の型によって使い分ける（関数オーバーロード）」という仕組みがあり、`nullptr`はその使い分けにも役立ちます。
しかしC言語には関数オーバーロードがないため、C言語での`nullptr`の利点は「ポインター専用として型で区別できること」だと覚えておきましょう。

## 2進整数定数

コンピュータの中身は、すべて`0`と`1`だけの数字（2進数）で動いています。
C23では、数字の先頭に`0b`または`0B`をつけることで、2進数の数値をそのままコードに書けるようになりました。

たとえば、ファイルの「読み取り・書き込み・実行」といった許可スイッチ（フラグ）を1ビットずつ割り当てるとき、2進数で書くとどのスイッチがオンになっているか一目でわかります。

```c
#define PERMISSION_READ    0b100U
#define PERMISSION_WRITE   0b010U
#define PERMISSION_EXECUTE 0b001U

unsigned int permissions = PERMISSION_READ | PERMISSION_WRITE;
```

この例では、左から順に「読み取り＝`100`」「書き込み＝`010`」「実行＝`001`」とビットの位置がそのまま見えています。
末尾の`U`は「符号なし整数（マイナスがない整数）」であることを表す目印です。
`|`（ビットOR）で組み合わせると、`permissions`は`0b110`（読み取りと書き込みがオン）になります。

2進数で書いても、整数型の大きさ（幅）や型変換のルールは10進数や16進数のときと変わりません。
書いた値が、入れる先の変数におさまる大きさかどうかを確認して使いましょう。

## 数値リテラルの桁区切り

`1000000`や`0b11111111`のように桁が多い数字は、0や1がいくつ並んでいるか数えにくいですよね。
普段の生活では`1,000,000`のようにカンマで区切りますが、C言語ではカンマに別の意味があるため使えません。

そこでC23では、整数定数や浮動小数点定数（小数の値）の数字のあいだに、単一引用符`'`（シングルクォート）を区切り文字として入れられるようになりました。
この`'`は人間が読みやすくするための飾りなので、計算するときはコンパイラに無視されます。

```c
unsigned int byte_mask = 0b1111'1111U;
unsigned long population = 1'000'000UL;
unsigned long color = 0xFF'80'20UL;
```

2進数は4桁ごと、10進数は3桁ごと、16進数は2桁ごとなど、見やすい場所で区切ることができます。

ただし、次のルールに気をつけてください。

- アンダースコア（`_`）はC23の桁区切りとしては使えません
- `0b`や`0x`などの接頭辞のすぐ後ろ（例：`0b'1111`）や、数字のいちばん最後（例：`1000'`）には置けません

## `auto`による型推論

普段C言語で変数を作るときは、`int count = 42;`のように最初に型を書きます。
C23では、変数を宣言するときに最初の値（初期化子）を書いておけば、型の代わりに`auto`と書くだけでコンパイラが自動で型を決めてくれるようになりました。
この仕組みを「型推論（かたすいろん）」といいます。

```c
auto count = 42;       /* int */
auto ratio = 3.14;     /* double */
auto pointer = &count; /* int * */
```

`42`は整数なので`count`は`int`型、`3.14`は小数なので`ratio`は`double`型、`&count`は`int`型の変数のアドレスなので`pointer`は`int *`型に自動で決まります。

`auto`を使うときは、必ず最初の値（初期化子）を書く必要があります。
値がないと、コンパイラは何の型にすればよいかわからないからです。
また、読む人に「ここは絶対に`double`型で計算したい」など型の意図をはっきり伝えたいときは、`auto`を使わずこれまで通り型名を書いた方が親切です。

## `constexpr`オブジェクト

プログラムの中で絶対に変えたくない値（定数）を作るとき、今までは`const`や`#define`を使ってきました。
C23で追加された`constexpr`を使うと、「プログラムを実行する前（コンパイル時＝翻訳時）に値が決まっている定数」をオブジェクトとして定義できます。

```c
constexpr int element_count = 100;
int values[element_count];
```

この例では、`element_count`がコンパイル時に確実に`100`だとわかっているため、配列の大きさとしてそのまま使えています。

`constexpr`で宣言する変数には、コンパイル時に計算できる定数式だけを初期値として書けます。
`const`との違いは次のとおりです。

- **`const`：** プログラムの実行中に値を書き換えないように守るための指定です
- **`constexpr`：** コンパイルの時点で値が決まっていて、配列のサイズ指定など「定数式が必要な場所」でも使える定数を作る指定です

## 条件付きインクルージョンの追加構文

プリプロセッサ（コンパイル前の下ごしらえをする仕組み）では、ある目印（マクロ）が定義されているかどうかで、使うコードを切り替えられます。
C23では、`#elif defined(...)`を短く書ける`#elifdef`と、`#elif !defined(...)`を短く書ける`#elifndef`が追加されました。

```c
#if defined(DEBUG)
#define LOG_LEVEL 2
#elifdef RELEASE
#define LOG_LEVEL 0
#elifndef LOG_LEVEL
#define LOG_LEVEL 1
#endif
```

このコードは次のように読めます。

1. もし`DEBUG`が定義されていたら、`LOG_LEVEL`を`2`にする
2. そうでなくて、もし`RELEASE`が定義されていたら、`LOG_LEVEL`を`0`にする
3. それにも当てはまらず、まだ`LOG_LEVEL`が定義されていなければ、`1`にする

これまでより短く書けるため、条件がいくつも続くときに見やすくなります。

## コンパイルと機能確認

C23のコードを試すときは、コンパイラに「C23のルールで翻訳してね」と指定します。
新しいコンパイラでは`-std=c23`を使いますが、C23が正式に決まる途中に作られたバージョンでは`-std=c2x`という名前を使うこともあります。

```bash
gcc -std=c23 -Wall -Wextra -pedantic source.c -o output
```

オプションの意味は次のとおりです。

- `-std=c23`：C23の規格に合わせてコンパイルする
- `-Wall -Wextra`：よくあるミスや気をつけたい部分を警告してくれる
- `-pedantic`：規格から外れた書き方がないか厳しくチェックしてくれる

どのオプション名が使えるか、どのC23機能が実装されているかは、コンパイラの種類やバージョンによって違います。
バージョン番号だけで「全部使えるはず」と判断せず、使いたい機能を入れた小さなテストコードを警告付きでコンパイルして確かめるのが確実です。

## 以前の規格から移行するときの確認事項

すでに動いているC99やC17などのプロジェクトをC23へ切り替えるときは、次の4点を確認しておくと安心です。

1. **処理系の対応：** 開発やビルドに使うすべてのコンパイラが、使いたいC23機能をサポートしているか確認します
2. **規格モード：** ビルドツール、コードのチェックツール（静的解析）、エディタの設定をすべて同じ規格モード（C23）にそろえます
3. **公開ヘッダー：** 自分のライブラリを使う相手が古い規格のコンパイラを使っている場合、外向けに公開するヘッダーファイルにはC23専用の書き方を含めない設計も考えます
4. **機械的な置換を避ける：** 今ある`NULL`をすべて無理やり`nullptr`に書き換える必要はなく、対応するコンパイラやチームのルールに合わせて少しずつ取り入れます
