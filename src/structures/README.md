# 構造体とポインター

## 対応C規格

- **主要対象：** C90/C11
- **学習内容：** 構造体の基本、構造体とポインター、構造体配列、複雑なデータ構造の構築

## 学習目標

この章を完了すると、以下のことができるようになります。

- 構造体の定義と使用ができる
- 構造体ポインターを適切に操作できる
- 構造体配列を操作できる
- 構造体の値渡しとポインター値の受け渡しを区別できる
- パディングを考慮して構造体のサイズを確認できる

## 概要と詳細

### 構造体とは

これまでの配列では、`int`型だけ、`char`型だけのように、同じ型のデータしかまとめられませんでした。
**構造体（struct）**は、異なる型の複数のデータを1つのまとまり（オブジェクト）にできる機能です。
C言語の専門用語では、複数のデータを組み合わせた型を**集成体型**と呼びます。

ゲームのキャラクターのステータス画面や、学校の生徒手帳をイメージするとわかりやすいでしょう。
1人の生徒には「名前（文字列）」「出席番号（整数）」「年齢（整数）」「成績（小数）」のように違う種類の情報がありますが、構造体を使うとこれらを1つの新しい型としてまとめて扱えます。
構造体の中に入っている1つひとつの変数のことを**メンバ**と呼びます。

#### 構造体で関連する値をまとめる

もし構造体がないと、生徒10人分の情報を管理するために、名前・番号・年齢の配列をバラバラに用意しなければなりません。
すると、「3番目の生徒のデータ」を扱うたびに3つの配列すべてを同じ添字（番号）で操作する必要があり、並べ替えなどをするときにミスが起きやすくなります。
構造体を使えば、1人分のデータが1つの箱にまとまるため、管理がとてもシンプルになります。

```c
/* 構造体を使わない場合は、値の対応関係を添字で管理する */
char names[10][50];
int ids[10];
int ages[10];

/* 構造体を使う場合は、学生ごとの値を一つの要素にまとめる */
struct student students[10];
```

### 構造体の基本概念

#### 構造体の定義

構造体を使うには、まず「どんなメンバを入れるか」という**設計図**を定義します。
設計図を書くだけではまだ変数は作られません。
終わりの閉じ波括弧`}`の後ろには、忘れずにセミコロン`;`を付けます。

```c
struct 構造体名 {
    データ型 メンバ名1;
    データ型 メンバ名2;
    /* ... */
};
```

#### 基本的な構造体の例

学生の情報、2次元座標（点の位置）、日付をそれぞれ構造体として定義する例です。
関連するデータ同士を1つの設計図にまとめています。

```c
/* 学生の情報を表す構造体 */
struct student {
    char name[50];
    int id;
    int age;
    float gpa;
};

/* 2次元座標を表す構造体 */
struct point {
    int x;
    int y;
};

/* 日付を表す構造体 */
struct date {
    int year;
    int month;
    int day;
};
```

### 構造体変数の宣言と初期化

#### 構造体変数の宣言

設計図（構造体の定義）ができたら、それをもとに実際の変数を作ります。
C言語では、`struct student`のように`struct`キーワードと構造体名をセットにして型名として書きます。

```c
struct student s1;           /* 単一の構造体変数 */
struct student s2, s3;       /* 複数の構造体変数 */
struct student class[30];    /* 構造体配列 */
```

#### 構造体の初期化

構造体変数に最初の値を入れる（初期化する）方法はいくつかあります。
宣言と同時に波括弧`{}`でメンバの順番通りに値を入れる方法と、C99以降で使える「`.メンバ名 = 値`」のように名前を指定して入れる方法（**メンバ指定初期化**）があります。
後から値を入れたい場合は、メンバごとに代入します（文字列の配列には`=`で代入できないため、`strcpy`関数を使います）。

```c
/* 宣言と同時に初期化 */
struct point p1 = {10, 20};

/* メンバ指定初期化（C99以降） */
struct point p2 = {.x = 15, .y = 25};

/* 後から初期化 */
struct student s;
strcpy(s.name, "山田太郎");
s.id = 12345;
s.age = 20;
s.gpa = 3.5;
```

### 構造体メンバのアクセス

構造体の中に入っているメンバを読み書きするには、変数そのものを使うか、ポインターを使うかによって演算子を使い分けます。

#### ドット演算子（.）

構造体変数そのものからメンバを取り出すときは、**ドット演算子（`.`）**を使います。
「箱`p`の中にある`x`」を`p.x`と書くイメージです。

```c
struct point p = {10, 20};

printf("x: %d\n", p.x);
printf("y: %d\n", p.y);

p.x = 30;  /* メンバの値を変更 */
p.y = 40;
```

#### アロー演算子（->）

構造体の場所（アドレス）を指しているポインターからメンバを取り出すときは、**アロー演算子（`->`）**を使います。
矢印の形をしているので、「ポインターが指している先の箱のメンバ」という意味が直感的にわかります。

```c
struct point p = {10, 20};
struct point *ptr = &p;

printf("x: %d\n", ptr->x);
printf("y: %d\n", ptr->y);

ptr->x = 50;  /* ポインター経由でメンバを変更 */
ptr->y = 60;
```

### 構造体とポインター

#### 構造体ポインターの基本

`ptr->name`は、実は`(*ptr).name`（まず`*ptr`でポインター先の構造体本体を取り出し、そのメンバ`.name`にアクセスする）を短く書きやすくしたものです。
`(*ptr).name`では丸括弧`()`を忘れると`.`の方が先に計算されてエラーになるため、ポインター経由のアクセスでは通常アロー演算子`->`を使います。

```c
struct student s = {"田中花子", 67890, 19, 3.8};
struct student *ptr = &s;

/* 以下は同じ結果 */
printf("Name: %s\n", s.name);
printf("Name: %s\n", ptr->name);
printf("Name: %s\n", (*ptr).name);
```

#### 構造体ポインターの利点

構造体を扱うときにポインターがよく使われるのには、次の3つの理由があります。

1. **コピーの回避**：構造体の中身を丸ごとコピーする代わりに、メモリの場所（ポインター値）だけを渡せるため、大きな構造体でも高速に処理できます
2. **呼び出し側の変更**：ポインターを通じて元の構造体を直接書き換えられます
3. **読み取り専用の指定**：`const struct point *`のように`const`を付けることで、「この関数は中身を読むだけで、絶対に書き換えません」という約束を型で示せます

### 構造体と関数

構造体を関数に渡す方法は、「値渡し」と「ポインター渡し」の2種類があります。

#### 構造体を値渡しする関数

構造体変数をそのまま引数に渡すと、構造体のコピーが作られて関数に渡されます。
ノートを1冊丸ごとコピーして渡すようなイメージなので、関数の中で`p.x`を書き換えても、呼び出し元の`p`には影響しません。

```c
void print_point(struct point p)
{
    printf("Point: (%d, %d)\n", p.x, p.y);
}

int main(void)
{
    struct point p = {10, 20};
    print_point(p);  /* 構造体のコピーが作られる */
    return 0;
}
```

#### 構造体ポインターを渡す関数

構造体のアドレス（`&p`）を渡すと、コピーを作らずに元の構造体を操作できます。
`print_point_ptr`のように表示だけしたい関数には`const`を付けて書き換えを防ぎ、`move_point`のように座標を移動させたい関数では`const`なしで中身を書き換えます。

```c
void print_point_ptr(const struct point *p)
{
    printf("Point: (%d, %d)\n", p->x, p->y);
}

void move_point(struct point *p, int dx, int dy)
{
    p->x += dx;
    p->y += dy;
}

int main(void)
{
    struct point p = {10, 20};
    print_point_ptr(&p);
    move_point(&p, 5, 3);
    print_point_ptr(&p);  /* (15, 23) */
    return 0;
}
```

#### 構造体を返す関数

関数の戻り値として構造体を返すこともできます。
C言語の関数は通常1つの値しか返せませんが、構造体を使えば`x`と`y`のような複数の値を1つにまとめて返せるので便利です。

```c
struct point add_points(struct point p1, struct point p2)
{
    struct point result;
    result.x = p1.x + p2.x;
    result.y = p1.y + p2.y;
    return result;
}

struct point create_point(int x, int y)
{
    struct point p = {x, y};
    return p;
}
```

### 構造体配列

構造体を配列として並べると、クラス全員の名簿や、ゲームに登場する複数の敵キャラクターなどをまとめて管理できます。

#### 構造体配列の宣言と初期化

通常の配列と同じように、`struct student class[3]`と書いて宣言します。
初期化するときは、1人分の波括弧`{}`をカンマで区切って並べます。

```c
/* 学生配列の宣言 */
struct student class[3];

/* 初期化 */
struct student class[3] = {
    {"山田太郎", 12345, 20, 3.5},
    {"佐藤花子", 12346, 19, 3.8},
    {"田中次郎", 12347, 21, 3.2}
};
```

#### 構造体配列の操作

`for`ループと組み合わせれば、全員の情報を順番に表示したり、特定のIDを持つ学生を探し出したりできます。
`class[i].name`は「配列`class`の`i`番目に入っている構造体の`name`メンバ」という意味です。

```c
int i;

/* 全学生の情報を表示 */
for (i = 0; i < 3; i++) {
    printf("Student %d: %s (ID: %d)\n",
           i+1, class[i].name, class[i].id);
}

/* 特定の学生を検索 */
for (i = 0; i < 3; i++) {
    if (class[i].id == 12346) {
        printf("Found: %s\n", class[i].name);
        break;
    }
}
```

### ネストした構造体

#### 構造体の中に構造体

構造体のメンバとして、別の構造体を入れることもできます。
これを**ネスト（入れ子）した構造体**と呼びます。
次の例では、`struct person`の中に誕生日を表す`struct date`を入れています。
内側のメンバを取り出すときは、`p.birthday.year`のようにドットを続けて書きます。

```c
struct date {
    int year;
    int month;
    int day;
};

struct person {
    char name[50];
    struct date birthday;  /* 構造体をメンバとして含む */
    int age;
};

/* 使用例 */
struct person p = {
    "鈴木一郎",
    {1990, 5, 15},  /* birthday */
    33
};

printf("Birthday: %04d-%02d-%02d\n",
       p.birthday.year, p.birthday.month, p.birthday.day);
```

### 構造体の動的メモリ割り当て

#### malloc()を使った構造体の動的確保

プログラムを実行している途中で「必要な数だけ構造体を作りたい」というときは、`malloc`関数を使ってメモリを動的に借りてきます（動的確保）。
メモリの確保に失敗すると`malloc`は`NULL`（どこも指していない空のポインター）を返すため、使う前に必ず`NULL`チェックを行います。
使い終わったメモリは、必ず`free`関数で返却します。

```c
#include <stdlib.h>

/* 単一の構造体を動的確保 */
struct student *s = malloc(sizeof *s);

if (s == NULL) {
    fprintf(stderr, "Allocation failed\n");
    return 1;
}

/* 構造体の使用 */
strcpy(s->name, "動的太郎");
s->id = 99999;
s->age = 22;

/* メモリ解放 */
free(s);
s = NULL;

/* 構造体配列を動的確保 */
int size = 100;
struct student *students = malloc((size_t)size * sizeof *students);

if (students != NULL) {
    /* 構造体配列を使用 */
    free(students);
}
```

C言語では、`malloc`が返す`void *`型は他のオブジェクトポインター型へ自動で変換されるため、`(struct student *)`のようなキャストを書く必要はありません。
また、`sizeof(struct student)`ではなく`sizeof *s`と書いておくと、あとでポインター`s`の型を変更したときも、確保するサイズが自動で新しい型に追従するためミスを防げます。

### typedefを使った構造体

#### `typedef`の利点

毎回`struct point`のように`struct`を付けて書くのは少し手間がかかります。
**`typedef`**を使うと、既存の型に好きな別名（あだ名）を付けられるため、`Point`のように短い名前で変数を宣言できるようになります。

```c
/* typedef なし */
struct point {
    int x;
    int y;
};
struct point p1, p2;  /* 毎回 struct が必要 */

/* typedef あり */
typedef struct {
    int x;
    int y;
} Point;

Point p1, p2;
```

#### `typedef`の使用例

複数の構造体に`typedef`で名前を付けておくと、プログラム全体がすっきり読みやすくなります。

```c
typedef struct {
    char name[50];
    int id;
    float gpa;
} Student;

typedef struct {
    int year;
    int month;
    int day;
} Date;

/* 使用が簡潔に */
Student s1, s2;
Date today = {2024, 12, 25};
```

### 共用体（union）

#### 共用体の基本概念

構造体によく似た仕組みに**共用体（`union`）**があります。
構造体ではすべてのメンバにそれぞれ別のメモリ領域が用意されますが、共用体では**すべてのメンバが同じ1つのメモリ領域を共有**します。

1つのロッカーを「整数を入れる用」「小数を入れる用」「文字を入れる用」で使い回すイメージです。
そのため、同時に保存できるのはどれか1つのメンバの値だけで、別のメンバに値を書き込むと前の値は上書きされます。

```c
union data {
    int i;
    float f;
    char c;
};

union data d;
d.i = 10;
printf("int: %d\n", d.i);

d.f = 3.14f;
printf("float: %.2f\n", d.f);
/* 最後に格納したメンバはd.f */
```

最後に値を書き込んだメンバ（上の例では`d.f`）とは別のメンバ（たとえば`d.i`）を読み出すと、メモリ上のビットの並びを無理やり別の型として解釈することになります。
その結果は型や環境によって異なり、コンピュータが不正な値として扱う**トラップ表現**になる可能性もあるため、共用体を型変換の代わりに使ってはいけません。

#### 共用体の用途

共用体は次のような場面で使われます。

- 同時には1つしか使わない複数のデータでメモリを節約したいとき
- 「今どのメンバが入っているか」を記録する別の変数（タグメンバ）と構造体で組み合わせて、複数種類のデータを1つの型で扱いたいとき

### 構造体の高度な使用法

構造体とポインターを組み合わせると、配列よりも柔軟なデータ構造を作ることができます。

#### 自己参照構造体（リンクリスト）

自分自身と同じ型の構造体へのポインターをメンバに持つ構造体を**自己参照構造体**と呼びます。
電車の車両同士が連結器でつながっているように、データ（`data`）と「次の車両の場所（`next`）」をつなげて並べたデータ構造が**リンクリスト**です。
一番最後の車両の`next`には、終点であることを表す`NULL`を入れます。

なお、構造体の定義の中で自分自身の型を指すポインターを書くときは、まだ`typedef`名の`Node`が完成していないため、`struct node *next;`のようにタグ名を使って書きます。

```c
typedef struct node {
    int data;
    struct node *next;  /* 自分自身の型へのポインター */
} Node;

/* リンクリストの簡単な例 */
Node *head = NULL;
Node *new_node = malloc(sizeof *new_node);
if (new_node != NULL) {
    new_node->data = 42;
    new_node->next = head;
    head = new_node;
}
```

#### 関数ポインターを含む構造体

構造体のメンバには、数値や文字列だけでなく「関数の場所（関数ポインター）」を入れることもできます。
次の例では、「操作の名前」と「実行する計算関数」をセットにした構造体を作っています。
関数ポインターの詳しい仕組みは、次の第12章で学びます。

```c
typedef struct {
    char name[20];
    int (*calculate)(int, int);
} Operation;

int add(int a, int b) { return a + b; }
int multiply(int a, int b) { return a * b; }

Operation ops[] = {
    {"加算", add},
    {"乗算", multiply}
};

/* 使用例 */
int result = ops[0].calculate(5, 3);  /* add(5, 3) */
```

### よくある間違いとデバッグ

構造体を使い始めたときによく起きる4つのミスと対策を確認しましょう。

#### 1. 構造体の比較

**問題：** 構造体同士を`==`で直接比較しようとしてしまうことがあります。
構造体の中には後で説明する「すき間（パディング）」が入る場合があるため、C言語では構造体同士の`==`比較は禁止されています。

```c
struct point p1 = {10, 20};
struct point p2 = {10, 20};
if (p1 == p2) { /* 制約違反：構造体には==を適用できない */ }
```

**対策：** メンバを1つずつ比べる関数を作ります。

```c
int points_equal(struct point p1, struct point p2)
{
    return (p1.x == p2.x && p1.y == p2.y);
}

if (points_equal(p1, p2)) { /* 正しい */ }
```

#### 2. 未初期化構造体の使用

**問題：** 構造体変数を宣言した直後は、中身に以前メモリに残っていたゴミのような値が入っています。
初期化せずに読み出すと、おかしな文字が表示されたり、プログラムが異常終了したりします。

```c
struct student s;
printf("Name: %s\n", s.name);  /* 未初期化データ */
```

**対策：** 宣言時に`{0}`で全メンバを0に初期化するか、`memset`で0埋めします。

```c
struct student s = {0};  /* ゼロ初期化 */
/* または */
memset(&s, 0, sizeof(s));
```

#### 3. 文字列の代入ミス

**問題：** 配列には`=`演算子で文字列を直接代入できません。

```c
struct student s;
s.name = "山田太郎";  /* 制約違反：配列には代入できない */
```

**対策：** `strcpy`関数（または安全に長さを制限できるコピー処理）を使って文字をコピーします。

```c
struct student s;
strcpy(s.name, "山田太郎");  /* strcpy を使用 */
```

#### 4. 構造体ポインターの初期化忘れ

**問題：** 構造体ポインターを宣言しただけで、実体のあるメモリを指させていない状態で`->`を使うと、でたらめな場所を書き換えてしまう**未定義動作**（プログラムの強制終了などの原因）になります。

```c
struct student *s;
strcpy(s->name, "太郎");  /* 未初期化ポインターの間接参照は未定義動作 */
```

**対策：** 既存の変数のアドレス（`&`）を入れるか、`malloc`でメモリを確保して`NULL`でないことを確認してから使います。

```c
struct student *s = malloc(sizeof *s);
if (s != NULL) {
    strcpy(s->name, "太郎");
}
```

### パフォーマンスとメモリ効率

#### 構造体のパディング

次の構造体は、`char`（1バイト）が2つ、`int`（多くの環境で4バイト）が1つなので、合計6バイトになりそうに見えます。
ところが実際に`sizeof(struct example)`を調べると、多くの環境では**12バイト**になります。

```c
struct example {
    char c;
    int i;
    char c2;
};
```

コンピュータのCPUは、データをメモリのキリのよい番地（たとえば4バイトの`int`型なら4の倍数の番地）に置いておくと、1回の動作で素早く読み書きできます。
この「データの型ごとに決まった区切り位置にそろえるルール」を**アラインメント**と呼びます。

コンパイラはアラインメントを守るため、各メンバの間や構造体の末尾に自動で空のすき間を挟みます。
このすき間が**パディング**です。
上の例では、`c`（1バイト）の後ろに3バイトのすき間、`i`（4バイト）、`c2`（1バイト）の後ろに3バイトのすき間が入り、合計12バイトになることがあります。
実際のサイズは環境によって変わるため、必ず`sizeof(struct example)`で確認します。

#### メモリ効率の改善

メンバを並べる順番を工夫し、サイズの大きい型から並べるようにすると、パディングが減って構造体のサイズが小さくなることがあります。
次の`struct good`では、`i`（4バイト）、`c1`（1バイト）、`c2`（1バイト）、末尾のすき間（2バイト）となり、合計8バイトに収まる場合があります。

```c
/* パディングが増える場合がある配置 */
struct bad {
    char c1;
    int i;
    char c2;
};

/* パディングが減る場合がある配置 */
struct good {
    int i;
    char c1;
    char c2;
};
```

メンバ順の変更でサイズが減るかどうかは、各型のサイズとアラインメントに依存します。
ただし、通信データやファイル形式、他のプログラムとの約束事（ABI）で順番が決まっている構造体では、メモリ節約だけを理由にメンバ順を勝手に変えてはいけません。

## C90とC11の違い

C言語の規格（バージョン）によって、構造体で使える便利な機能が少しずつ増えています。

### C90での制限

- メンバ指定初期化（`.x = 15`のような書き方）が使えない
- ブロック内の変数宣言は、そのブロックの処理文より前にまとめて書く必要がある
- コメントは`/* */`のみ使用できる

### C11での拡張

- **匿名構造体・共用体**：構造体の中に名前を付けずに別の構造体や共用体を入れられる
- **`_Static_assert`**：コンパイル時に構造体のサイズが期待通りかどうかを自動チェックできる

なお、メンバ指定初期化はC99で追加された機能であり、C11固有ではありません。
