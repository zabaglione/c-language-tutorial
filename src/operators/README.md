# 第4章：演算子と式

## 対応するC規格

- **主要対象**：C90
- **学習内容**：算術、代入、比較、論理、ビット、条件、`sizeof`、優先順位

## 学習目標

この章では、計算をしたり、値を比べたり、条件を組み合わせたりするための記号（**演算子**）と、それらを組み合わせた**式**のルールを学びます。

- 整数どうしの計算と、小数（浮動小数点）の計算を区別できる
- 前置・後置の`++`と`--`の違いを使い分けられる
- 論理演算子の「短絡評価」の仕組みを説明できる
- ビットシフトで未定義動作や処理系定義の動作を避けられる
- 演算子の「優先順位」と、実際に計算する順番（評価順序）の違いを区別できる

## 算術演算子

足し算や引き算などの基本的な計算をする演算子です。

| 演算子 | 意味 | 例 |
|---|---|---|
| `+` | 加算（足し算） | `a + b` |
| `-` | 減算（引き算） | `a - b` |
| `*` | 乗算（掛け算） | `a * b` |
| `/` | 除算（割り算） | `a / b` |
| `%` | 剰余（割り算のあまり） | `a % b` |

整数どうしを計算すると、答えも原則として整数型になります。
そのため、割り算では小数点以下が切り捨てられます。

```c
int total = 7;
int count = 2;
int quotient = total / count;           /* 3 */
double average = (double)total / count; /* 3.5 */
```

`7 / 2`は整数どうしなので`3`になります。
`3.5`という小数の答えがほしいときは、`(double)total`のように片方を小数型へキャストしてから割ります。

ここで気をつけるべきルールが2つあります。
1つ目は、`0`で割る整数除算とあまり（`%`）の計算は**未定義動作**（ルール違反で何が起きるかわからない状態）になることです。
2つ目は、符号付き整数の足し算・引き算・掛け算で、答えがその型の範囲に入りきらなくなった場合（オーバーフロー）も未定義動作になることです。

C99以降の整数除算では、小数点以下を0の方向へ切り捨てる決まりになっています。
一方、C90ではマイナスの数を含む割り算やあまりの丸め方向が環境ごとの決まり（処理系定義）だったため、どの環境でも同じ結果にしたいC90コードではマイナスの割り算・あまりに頼らないようにします。

あまりの計算（`%`）は、偶数・奇数の判定や、決まった周期でくり返す処理にとても便利です。

```c
if (number % 2 == 0) {
    printf("even\n");
}
```

この例では、`number`を2で割ったあまりが`0`なら偶数（`even`）と表示します。

## 代入演算子

単純代入`=`は、右側の値を左側の変数の型へ変換してから箱の中へ入れます。
また、`+=`や`-=`のように「計算してから入れ直す」操作を短く書ける**複合代入演算子**があります。

```c
int score = 100;

score += 20;
score -= 5;
score *= 2;
score /= 5;
score %= 7;
```

この例では、`score`は`100`から始まり、`+20`で`120`、`-5`で`115`、`*2`で`230`、`/5`で`46`、`%7`で`4`へと変化します。

`E1 op= E2`という形は、おおむね`E1 = E1 op E2`と同じ意味ですが、「左側の`E1`が1回しか評価されない」という違いがあります。
左側に配列の要素やポインターの間接参照などが入っているとき、この違いが大切になります。

## インクリメントとデクリメント

変数の値を1だけ増やす`++`を**インクリメント**、1だけ減らす`--`を**デクリメント**と呼びます。
変数の前に置くか（**前置**）、後ろに置くか（**後置**）で、式全体が返す値のタイミングが変わります。

- **前置（`++a`）**：先に1増やしてから、増えたあとの新しい値を式の結果にします。
- **後置（`b++`）**：今の値を式の結果として渡してから、あとで1増やします。

```c
int a = 5;
int b = 5;
int x = ++a; /* a == 6, x == 6 */
int y = b++; /* b == 6, y == 5 */
```

この例では、`a`も`b`も最終的には`6`になりますが、`x`には増えたあとの`6`、`y`には増える前の`5`が入ります。

増やした値をその場で使わず、ただ1増やしたいだけのときは、単独の文として`i++;`または`++i;`と書けます。
また、プログラムを読みやすく安全に保つため、1つの式の中で同じ変数を2回以上更新してはいけません。

```c
int n = 0;
int result = n++ + n++; /* Undefined behavior. */
```

C90とC99の用語では、値の更新が確定する区切り（**シーケンスポイント**）が来る前に同じ変数を複数回書き換えてしまうため、このような式は未定義動作になります。

## 関係演算子と等価演算子

2つの値を比べて、大小や等しいかどうかを調べる演算子です。

| 演算子 | 意味 |
|---|---|
| `<` | より小さい |
| `<=` | 以下 |
| `>` | より大きい |
| `>=` | 以上 |
| `==` | 等しい |
| `!=` | 等しくない |

比較した結果は`int`型の値になり、正しければ（**真**なら）`1`、間違っていれば（**偽**なら）`0`になります。
C90には真・偽だけを表す専用の型（ブール型）がないため、`if`文などの条件式では`0`を偽、`0`以外をすべて真として扱います。

```c
if (count == 0) {
    printf("empty\n");
}
```

とてもよくある間違いが、「代入の`=`」と「比較の`==`」の書き間違いです。
もし条件式の中でわざと代入を使いたい場合は、書き間違いではないとひと目でわかるように括弧で囲みます。

```c
if ((ch = getchar()) != EOF) {
    putchar(ch);
}
```

この例では、1文字読み取って`ch`へ入れ、それが入力の終わり（`EOF`）でなければそのまま画面へ出力しています。

なお、小数（浮動小数点数）には計算の途中でわずかな丸め誤差が入ることがあるため、計算結果を`==`でぴったり一致するか比べてよいかは計算内容によって慎重に判断します。
「どれくらいの差なら同じとみなすか」という幅（許容誤差）を使う場合も、適当な固定値を選ぶのではなく、扱う値の大きさや必要な精度に合わせて決めます。

## 論理演算子

複数の条件を「かつ」「または」「ではない」で組み合わせる演算子です。

| 演算子 | 意味 |
|---|---|
| `&&` | 論理積（両方が真なら真＝「かつ」） |
| `\|\|` | 論理和（どちらかが真なら真＝「または」） |
| `!` | 論理否定（真と偽を逆にする＝「ではない」） |

論理演算子の結果も、`int`型の`0`か`1`になります。
`!value`は、`value`が`0`（偽）なら`1`（真）に、`0`以外（真）なら`0`（偽）になります。

### 短絡評価

`&&`と`||`には、**短絡評価**という賢いルールがあります。
左側を計算しただけで全体の答えが確定したら、右側を計算せずにスキップする仕組みです。

- `left && right`：`left`が`0`（偽）なら、右側が何であっても全体は偽になるので、`right`は評価しません。
- `left || right`：`left`が`0`以外（真）なら、右側が何であっても全体は真になるので、`right`は評価しません。

この仕組みのおかげで、危険な計算をする前に「安全かどうか」を左側で先にチェックできます。

```c
if (divisor != 0 && value / divisor > 10) {
    printf("large quotient\n");
}
```

もし`divisor`が`0`だった場合、左側の`divisor != 0`が偽になるため、右側の`value / divisor`（0での割り算）は実行されずに安全にスキップされます。

同じように、ポインター（メモリの場所を指す変数）が空っぽ（`NULL`）でないことを先に確認する場面でも大活躍します。

```c
if (ptr != NULL && *ptr == 'A') {
    printf("match\n");
}
```

一方で、右側に「変数の値を変える処理（副作用）」を書くと、左側の結果しだいで実行されないことがあるため注意が必要です。

```c
int x = 0;
int y = 0;
int result = x && ++y; /* y remains 0. */
```

ここでは`x`が`0`なので右側の`++y`はスキップされ、`y`は`0`のままになります。
変数を更新することが目的なら、論理式の中に混ぜず、独立した文として書いたほうがずっと読みやすく安全です。

## ビット演算子

コンピューターの中の数は、0と1の並び（2進数）でできています。
この0と1の1桁（**ビット**）を直接スイッチのように操作するのが**ビット演算子**です。

| 演算子 | 意味 |
|---|---|
| `&` | ビット単位のAND（両方1なら1） |
| `\|` | ビット単位のOR（どちらか1なら1） |
| `^` | ビット単位のXOR（違えば1、同じなら0） |
| `~` | ビット反転（0と1をすべて入れ替える） |
| `<<` | 左シフト（ビットの並びを左へずらす） |
| `>>` | 右シフト（ビットの並びを右へずらす） |

複数のON/OFFのスイッチを1つの整数にまとめて管理する（ビット集合・フラグ管理）ときは、符号なし整数型を使うとルールがわかりやすくなります。

```c
unsigned int read_flag = 1u << 0;
unsigned int write_flag = 1u << 1;
unsigned int flags = read_flag | write_flag;

if ((flags & read_flag) != 0u) {
    printf("read enabled\n");
}
```

この例では、0番目のビットを「読み込み許可」、1番目のビットを「書き込み許可」に割り当て、`flags`の中に両方のスイッチを`|`で合成しています。
そして`flags & read_flag`で「読み込み許可のスイッチがONになっているか」を調べています。
数字の後ろの`u`は「符号なし整数（`unsigned`）ですよ」という目印です。

なお、`char`や`short`などの小さい型にビット演算を行うと、計算前に自動的に`int`型へ広がる**整数拡張**が起きます。
たとえば`a`が`unsigned char`であっても、`~a`の計算結果は通常`int`型になります。
元の型に戻したいときは、次のように明示的にキャストします。

```c
unsigned char a = 5u;
unsigned char inverted = (unsigned char)~a;
```

### シフトの条件

ビットを左右にずらすシフト演算（`<<`と`>>`）には、守らなければならない大切な条件があります。

- ずらす回数（シフト回数）がマイナスの場合、または左側の型（整数拡張後）のビット幅以上の場合、動作は未定義です。
- 符号付きのマイナスの数を左シフトすることも未定義動作です。
- 符号付きの0以上の数を左シフトできるのは、ずらした結果がその型に収まる場合だけです。
- 符号なし整数を右シフトすると、空いた上位（左端）のビットには必ず`0`が入ります。
- 符号付きのマイナスの数を右シフトした結果は、処理系定義（環境によって異なる）です。

安全でわかりやすいビットシフトを行うには、符号なし整数型を使い、シフト回数がビット幅未満であることを確認するのが基本です。

## 条件演算子

条件演算子`?:`は、条件が真か偽かによって2つの式のうち一方だけを選び、その値を返す演算子です。
`条件 ? 真のときの値 : 偽のときの値`の形で書きます。

```c
int max = a > b ? a : b;
```

上の例では、`a > b`が真なら`a`、偽なら`b`が`max`に入ります。
このように短い値の選択には便利ですが、変数を書き換えるような長い処理は無理に`?:`を使わず、`if`文で書いたほうが読みやすくなります。

## `sizeof`演算子

`sizeof`は、型や変数がメモリ上で何バイト占めているかを`size_t`型で返す演算子です。
C90で`printf`を使って表示するときは、値が`unsigned long`に収まることを前提にキャストして`%lu`で出力します。

```c
int values[10];

printf("int: %lu bytes\n", (unsigned long)sizeof(int));
printf("array: %lu bytes\n", (unsigned long)sizeof values);
```

## 優先順位と評価順序

算数で「足し算より掛け算を先にまとめる」というルールがあるように、C言語の演算子にも**優先順位**があります。
ただし、優先順位が決めるのは「どの演算子がどの値とくっつくか」という組み合わせ方だけであり、「左右のどちらを先に計算するか（**評価順序**）」を決めるものではありません。

```c
int result = a + b * c; /* a + (b * c) */
```

関数の引数など、C言語の多くの式では「どちらの引数を先に計算するか」という評価順序が決まっていません。
そのため、計算の順番によって結果が変わる処理（副作用がある処理）は、1つの式に詰め込まず、複数の文へ分けて書きます。

```c
int first = f();
int second = g();
int result = combine(first, second);
```

このように分けて書けば、必ず`f()`が先、`g()`が後という順番がはっきり保証されます。

論理演算子では、`!`、`&&`、`||`の順に強く結び付きます。
ただ、優先順位を覚えていたとしても、条件のまとまりがひと目で読み取りにくいときは積極的に括弧をつけましょう。

```c
if (is_admin || (is_member && has_permission)) {
    printf("allowed\n");
}
```

括弧をつけることで、あとから読み返したときにも「どんな条件なのか」がすぐに伝わるプログラムになります。
