# 第8章：ポインタの基本

## 対応するC規格

- **主要対象**：C90
- **学習内容**：ポインター、間接参照、配列との関係、関数引数、動的メモリ確保

## 学習目標

この章では、データの場所を指し示す**ポインター**の基本を学びます。
ポインターを理解すると、配列や関数、大きなデータを効率よく扱えるようになります。

- ポインターを宣言し、変数の場所（アドレス）を格納できる
- ポインターを通して安全に値を読んだり書き換えたりできる条件を説明できる
- 配列とポインターの関係や、ポインターを移動できる範囲を説明できる
- ポインターを関数へ渡して、呼び出し元の変数の値を変更できる
- 実行中に確保したメモリの管理と解放ができる

## ポインタとは

コンピュータの中には、数値や文字などのデータをしまっておく**メモリ**という場所があります。
メモリは、番号のついたたくさんのロッカーがずらっと並んでいる様子をイメージするとわかりやすいです。

ふつうの変数（たとえば`int value = 42;`）は、ロッカーの中に`42`という値を入れて、そのロッカーに`value`という名前をつけた状態です。
一方で**ポインター**は、ロッカーの中身そのものではなく、「どの番号のロッカーに入っているか」という**場所の番号（アドレス）**をしまっておくための特別な変数です。
「ロッカーの番号を書いたメモ」と考えるとイメージしやすいでしょう。

ポインターを宣言するときは、変数名の前に`*`をつけます。
`*`より左側に書いた型は、「その番号のロッカーにどんな種類のデータが入っているか」を表します。

```c
int *int_pointer;
double *double_pointer;
```

上の例では、`int_pointer`は`int`型のデータが入っているロッカーを指すポインター、`double_pointer`は`double`型のデータが入っているロッカーを指すポインターになります。

関数の中で宣言しただけのポインター（未初期化の自動変数）には、以前メモリに残っていたでたらめな値（不定値）が入っています。
でたらめな番号のロッカーを勝手に開けると危険なので、使う前に必ず有効なアドレスか、**ヌルポインター**（`NULL`）で初期化します。

```c
int *pointer = NULL;
```

ヌルポインターは、「今はどのロッカーも指していない」という特別な印です。
どの場所も指していないヌルポインターを使って中身を取り出そうとする（間接参照する）と、**未定義動作**になります。
未定義動作とは、C言語のルール違反のことで、プログラムが強制終了したり、予想できないおかしな動きをしたりする危険な状態です。

## アドレス演算子と間接演算子

ポインターを扱うときは、`&`と`*`という2つの演算子を使います。

- **アドレス演算子`&`**：変数の前につけると、その変数がどのロッカーにあるか（アドレス）を取り出します
- **間接演算子`*`**：有効なポインターの前につけると、メモに書かれた番号のロッカーを開けて、中身を読んだり書き換えたりします（この操作を**間接参照**といいます）

次のプログラムで、実際に動きを確認してみましょう。

```c
#include <stdio.h>

int main(void)
{
    int value = 42;
    int *pointer = &value;

    printf("value: %d\n", value);
    printf("through pointer: %d\n", *pointer);
    printf("address: %p\n", (void *)pointer);
    return 0;
}
```

このプログラムでは、まず`value`という箱に`42`を入れ、次に`&value`でその場所の番号を調べて`pointer`にメモしています。
すると、`*pointer`は「`pointer`に書かれた番号のロッカーの中身」を表すため、`value`と同じ`42`が表示されます。

アドレスを表示するときに使う`printf`の`%p`は、`void *`型（どんな型のデータのアドレスでも受け取れる共通のポインター型）の値を渡す決まりです。
そのため、表示するときは`(void *)pointer`のように`void *`へ変換して渡します。
アドレスがどのような見た目で表示されるかは使う環境によって決まっており（処理系定義）、常に16進数になるとは限りません。

また、`*pointer`のように間接参照した式は、指しているロッカーそのものを表す**左辺値**（代入の左側に書いて中身を書き換えられるもの）になります。

```c
int value = 10;
int *pointer = &value;

*pointer = 20; /* value becomes 20. */
```

`*pointer = 20;`を実行すると、`pointer`が指しているロッカーの中身が`20`に書き換わるため、`value`の値も`20`に変わります。

## ポインタと配列

配列とポインターはよく一緒に使われますが、もともとは別々のものです。
配列は「同じ型のロッカーが隣り合って並んだまとまり」であり、ポインターは「ロッカー番号を1つだけ書いたメモ」です。

ただしC言語には、「配列の名前を式の中で使うと、たいていの場面で**先頭要素を指すポインター**に自動で変換される」というルールがあります。

```c
int values[5] = { 10, 20, 30, 40, 50 };
int *pointer = values; /* Same value as &values[0]. */
```

この例では、`values`と書くだけで、`&values[0]`（0番目のロッカーのアドレス）と同じ意味になります。

さらにC言語では、配列の添字記法`values[i]`は`*(values + i)`（先頭から`i`個隣のロッカーを開ける）と同じルールで定義されています。
そのため、ポインターに整数を足してから`*`で開けることでも、配列の各要素を順番に読み取れます。

```c
int i;

for (i = 0; i < 5; i++) {
    printf("%d\n", *(pointer + i));
}
```

このループでは、`i`が`0`から`4`まで増えるたびに、先頭から0個隣、1個隣、2個隣……と順番に中身を取り出して表示しています。

### 配列とポインタが異なる場面

配列の名前はいつもポインターに変換されるわけではありません。
代表的な例外が2つあります。

1つ目は、データの大きさ（バイト数）を調べる`sizeof`演算子の対象にしたときです。
この場面では、配列からポインターへの変換は起こりません。

```c
int values[5];
int *pointer = values;

sizeof values;  /* Size of the entire array. */
sizeof pointer; /* Size of the pointer object. */
```

`sizeof values`は「`int`5個分の配列全体の大きさ」になりますが、`sizeof pointer`は「ロッカー番号を書いたメモ1枚分の大きさ」になります。

2つ目は、単項`&`演算子の対象にしたときです。
`&values`の型は「5個の`int`の配列全体を指すポインター」であり、`&values[0]`の型である`int *`（`int`1個を指すポインター）とは型が異なります。

## ポインタ演算

データを指すポインターには、整数を足したり引いたりできます。
この計算を**ポインター演算**といいます。
ポインターに`+ 1`すると、メモリ上で1バイト進むのではなく、「その型1個分の大きさ」だけ自動で隣の要素へ移動します。

```c
int values[5];
int *begin = &values[0];
int *third = begin + 2;
```

上の例では、`begin`が0番目の要素を指しているため、`begin + 2`は2つ先の要素である`values[2]`（3番目の要素）を指します。

ポインター演算で動かしてよい範囲には、大切なルールがあります。
動かせるのは「同じ配列の要素」と、その**末尾の1つ後ろ**（配列のすぐ外側の目印）までです。
末尾の1つ後ろを指すポインターは、「もう終わりに着いたか」を比べるループの終了判定には使えますが、そこにデータは存在しないため`*`で間接参照してはいけません。

```c
int *current;
int *end = values + 5;

for (current = values; current != end; current++) {
    printf("%d\n", *current);
}
```

このコードでは、`end`に「最後の要素の1つ後ろ」を覚えておき、`current`を1つずつ進めながら`end`にたどり着くまで中身を表示しています。

なお、別々の配列を指しているポインター同士を引き算したり、大小を比べたりしてはいけません。
同じ配列の中を指す2つのポインターを引き算すると、「何要素ぶん離れているか」が求まり、その結果の型は`ptrdiff_t`という専用の整数型になります。

## ポインタを関数へ渡す

C言語で関数に引数を渡すときは、基本的に値のコピーが渡されます（これを**値渡し**といいます）。
コピーされた値を関数の中で書き換えても、呼び出し元の変数は変わりません。

そこで、変数の値ではなく**アドレス（ポインター）**を関数へ渡します。
すると関数は、受け取った番号のロッカーを直接開けて、呼び出し元の変数の値を書き換えられます。

次の`swap`関数は、2つの変数の値を入れ替える例です。

```c
void swap(int *left, int *right)
{
    int temporary;

    if (left == NULL || right == NULL) {
        return;
    }

    temporary = *left;
    *left = *right;
    *right = temporary;
}
```

```c
int a = 10;
int b = 20;

swap(&a, &b);
```

呼び出し側で`swap(&a, &b)`のように`&`をつけてアドレスを渡すと、`swap`関数の中の`left`は`a`を、`right`は`b`を指します。
関数の中で`*left`と`*right`を使って値を入れ替えることで、`main`側にある`a`と`b`の中身が入れ替わります。

また、もし間違って`NULL`が渡されたまま`*left`を実行すると未定義動作になるため、最初に`if (left == NULL || right == NULL)`で安全確認をしています。
関数を設計するときは、「ヌルポインターを渡してはいけない」というルール（事前条件）を説明書のように明確にしておくか、この例のように間接参照する前にチェックするようにします。

## 配列を関数へ渡す

関数の引数に配列を書くこともできますが、C言語では仮引数の配列宣言は自動的に対応するポインター型に読み替えられます（型調整）。
そのため、次の2つの宣言は関数としてまったく同じ意味になります。

```c
void process(int values[], int count);
void process(int *values, int count);
```

関数に渡されるのは配列全体のコピーではなく、先頭要素のアドレスだけです。
受け取った関数側では配列にいくつ要素が入っているかわからないため、要素数（`count`）を別の引数で一緒に渡すのが基本です。

```c
int sum_array(const int values[], int count)
{
    int sum = 0;
    int i;

    if (values == NULL || count < 0) {
        return 0;
    }

    for (i = 0; i < count; i++) {
        sum += values[i];
    }

    return sum;
}
```

仮引数に`const`をつけているのは、「この関数の中では配列の中身を読むだけで、書き換えません」という約束を表すためです。
なお、この例では足し算の結果が`int`型で表せる範囲を超えないことを呼び出し側の前提にしています。
エラーが起きた場合と、正しい合計値が`0`になった場合をきちんと区別したいときは、エラーの有無を戻り値で返し、計算結果は別のポインター引数へ書き込む設計にします。

## 関数からポインタを返す

関数からポインターを返すこともできますが、とても大切な注意点があります。
返すポインターは、**関数が終わったあとも消えずに残っているデータ**を指していなければなりません。

関数の中でふつうに宣言したローカル変数（自動記憶域期間を持つ変数）は、関数が終了するとメモリから片付けられてしまいます。
そのため、ローカル変数のアドレスを返してはいけません。

```c
int *invalid_pointer(void)
{
    int local = 10;
    return &local; /* Invalid after the function returns. */
}
```

上の例では、返却された時点で`local`のロッカーはもう使えなくなっているため、呼び出し元がそのポインターを使うと未定義動作になります。

一方で、`static`をつけて宣言した変数（静的記憶域期間を持つ変数）は、プログラムが終わるまでずっとメモリに残り続けるため、アドレスを返しても有効です。

```c
int *shared_value(void)
{
    static int value;
    return &value;
}
```

ただし、`static`変数は関数を何度呼び出しても同じ1つのロッカーを使い回します。
そのため、関数が途中でもう一度呼ばれたり（再入）、複数の処理が同時に実行されたり（並行実行）すると、値がぶつかってしまう点に注意が必要です。

呼び出しごとに別々の新しいデータを作って呼び出し側へ管理（所有権）を渡したい場合は、あとで説明する**動的メモリ確保**を使う方法もあります。

## 文字列とポインタ

C言語では、`"Hello"`のようにダブルクォートで囲んだ文字の並びを**文字列リテラル**といいます。
文字列リテラルを使って文字配列を初期化すると、配列の中に文字がコピーされるため、あとから中身を書き換えられます。

```c
char text[] = "Hello";
text[0] = 'h';
```

一方で、文字列リテラルを直接ポインターで指すこともできます。
ただし、文字列リテラルそのものは書き換え禁止の領域に置かれることがあるため、ポインターを通して文字を変更すると未定義動作になります。
C90でも、変更しないことをはっきり示すために`const char *`型で受け取ります。

```c
const char *text = "Hello";
```

C言語の文字列は、最後に終わりを表す特別な文字`'\0'`（ヌル文字）が置かれます。
文字列を扱うときは、文字の数だけでなく、この終端文字1個分の場所も含めて配列の大きさを管理する必要があります。

## 2次元配列へのポインタ

2次元配列は、表のように「行（横一列の配列）」がいくつも並んだデータです。
C言語では、2次元配列の1つの要素は「1行分の配列」と考えます。

```c
int matrix[3][4];
int (*row_pointer)[4] = matrix;
```

上の例では、`matrix`は「`int`が4個並んだ行」が3段ある配列です。
`int (*row_pointer)[4]`は、「`int`4個からなる1行を指すポインター」という意味になります。
ここで`row_pointer + 1`を計算すると、`int`1個分ではなく、`int`4個分まるごと進んで次の行の先頭を指します。

2次元配列の要素には、ポインター演算を使って次のようにアクセスできます。

```c
matrix[2][3] == *(*(matrix + 2) + 3)
```

`matrix + 2`で2番目の行（3段目）へ移動し、`*(matrix + 2)`でその行を取り出し、さらに`+ 3`で3番目の列（4列目）へ移動して中身を取り出しています。

2次元配列を関数へ渡すときも、次の行へ進むために「1行に何個並んでいるか（列数）」の情報が必要です。
そのため、最初の次元（行数）は省略できても、2つ目以降の次元（この例では`4`）は必ず型に書きます。

```c
void clear_matrix(int matrix[][4], int rows)
{
    int row;
    int column;

    for (row = 0; row < rows; row++) {
        for (column = 0; column < 4; column++) {
            matrix[row][column] = 0;
        }
    }
}
```

## 動的メモリ確保

これまでの配列は、プログラムを書く段階で「5個」「100個」と大きさを決めておく必要がありました。
しかし、プログラムを実行してから「ユーザーが入力した人数分だけロッカーを借りたい」という場面もあります。
このように、実行中に必要な大きさのメモリを借りて、使い終わったら返す仕組みを**動的メモリ確保**といいます。

動的メモリ確保に使う`malloc`、`calloc`、`realloc`、`free`という関数は、`<stdlib.h>`で宣言されています。
C言語では、`malloc`が返す`void *`はそのまま他の型のポインター変数へ代入できるため、`(int *)`のようなキャストは書く必要がありません。

```c
#include <stdlib.h>

int *allocate_values(size_t count)
{
    int *values;

    if (count == 0 || count > (size_t)-1 / sizeof *values) {
        return NULL;
    }

    values = malloc(count * sizeof *values);
    return values;
}
```

この関数では、`malloc`を呼ぶ前に安全チェックをしています。
`size_t`はメモリの大きさや個数を表す0以上の整数型で、`(size_t)-1`は`size_t`で表せる最大値を意味します。
個数が0のときや、`count * sizeof *values`の掛け算が最大値を超えて桁あふれ（オーバーフロー）しそうなときは、確保せずに`NULL`を返しています。

`malloc`は、要求した大きさのメモリを確保できなかった場合にヌルポインター（`NULL`）を返します。
また、確保に成功した直後のメモリの中身は不定（前のデータが残っている状態）なので、読む前に必ず値を書き込みます。

```c
int *values = allocate_values(100);

if (values == NULL) {
    return 1;
}

/* Use values here. */
free(values);
values = NULL;
```

借りたメモリを使い終わったら、必ず`free`関数で返却します。
返却したあとに`values = NULL;`と入れておくと、うっかり返却済みのロッカーをもう一度使ってしまうミスを防ぎやすくなります。

`free`に渡してよいのは、動的メモリ確保関数が返したポインターか、ヌルポインターだけです。
同じ場所を2回`free`したり、借りた配列の途中を指すポインターを渡したりすると、未定義動作になります。

### `calloc`

`calloc`は、「要素数」と「1要素の大きさ」の2つを指定してメモリを確保し、確保した領域の全ビットを`0`で埋めてくれます。
整数の配列をすべて`0`で初期化したいときに便利です。
ただし、全ビットが`0`の状態が、すべての環境でヌルポインターや浮動小数点数の`0.0`と同じ表現になることまでは標準Cは保証していません。

```c
int *values = calloc(count, sizeof *values);
```

要素数と要素サイズの掛け算は`calloc`側で計算してくれますが、確保に失敗すると`NULL`が返るため、使う前のチェックは必ず行います。

### `realloc`

`realloc`は、すでに借りているメモリの大きさをあとから広げたり縮めたりする関数です。
もし大きさの変更に失敗すると、`realloc`は`NULL`を返しますが、**元のメモリ領域は解放されずにそのまま残ります**。
そのため、戻り値を元のポインター変数へ直接上書きしてしまうと、失敗したときに元の場所の番号を失ってしまい、メモリを返却できなくなります。

```c
int *temporary;

temporary = realloc(values, new_count * sizeof *values);

if (temporary == NULL) {
    /* values still refers to the original allocation. */
} else {
    values = temporary;
}
```

このように、いったん`temporary`という別の一時変数で受け取り、`NULL`でないことを確かめてから`values`を更新するのが安全な書き方です。
この例でも、`new_count * sizeof *values`が`size_t`の範囲を超えないことを事前に確認する必要があります。
また、大きさに`0`を渡したときの`realloc`の動きはC規格のバージョンや処理系によって違いがあるため、メモリを解放したいときは必ず`free`を明示的に使います。

## 二重ポインタ

**二重ポインター**は、「ポインターを指すポインター」です。
ロッカーの例でいうと、「ロッカー番号を書いたメモが、どの引き出しに入っているか」を記録したメモにあたります。

ふつうのポインターを関数に渡すと「指している先の中身」を書き換えられますが、二重ポインターを関数に渡すと「呼び出し元のポインター変数そのもの（どこを指しているか）」を書き換えられます。

```c
int allocate_one(int **result)
{
    int *value;

    if (result == NULL) {
        return 0;
    }

    value = malloc(sizeof *value);

    if (value == NULL) {
        return 0;
    }

    *value = 0;
    *result = value;
    return 1;
}
```

この関数では、`malloc`で新しく確保したメモリのアドレスを`*result = value;`によって呼び出し元のポインター変数へ書き込んでいます。
呼び出し側は、戻り値が`1`（成功）のときに受け取ったメモリを使い、使い終わったら`free`で解放します。

## 関数ポインタ

ポインターは変数だけでなく、**関数そのものの場所**を指すこともできます。
これを**関数ポインター**といい、引数や戻り値の型が一致する関数をしまっておけます。
状況に応じて「足し算をする関数」と「引き算をする関数」を切り替えて呼び出すような場面で役立ちます。

```c
int add(int left, int right)
{
    return left + right;
}

int main(void)
{
    int (*operation)(int, int) = add;
    int result = operation(2, 3);

    return result == 5 ? 0 : 1;
}
```

`int (*operation)(int, int)`は、「`int`を2つ受け取って`int`を返す関数を指すポインター」という宣言です。
ここでは`operation`に`add`関数を代入し、`operation(2, 3)`と書いて呼び出しています。

なお、データを指すポインターと関数を指すポインターは別の種類として扱われます。
標準Cでは、関数ポインターと`void *`を相互に変換できるとは保証されていません。

## よくある誤り

ポインターはとても便利ですが、使い方を間違えると見つけにくいバグ（未定義動作）につながります。
特に起こりやすい4つのミスを確認しておきましょう。

### 未初期化ポインタ

ポインターを初期化しないまま`*pointer`で書き込もうとすると、でたらめな場所のメモリを壊してしまいます。

```c
int *pointer;
*pointer = 10; /* Undefined behavior. */
```

### 解放後の使用

`free`で返却したあとのメモリは、もう自分のものではありません。
返却済みのポインターを使って読み書きすると未定義動作になるため、`free`の直後に`NULL`を代入する習慣をつけると安全です。

```c
int *pointer = malloc(sizeof *pointer);

if (pointer != NULL) {
    free(pointer);
    /* *pointer = 10; */ /* Undefined behavior. */
    pointer = NULL;
}
```

### 配列の範囲外への移動

配列の末尾の1つ後ろを超えてさらに先へポインターを進めることは、中身を読まなくても計算しただけで未定義動作になります。

```c
int values[5];
int *invalid = values + 6; /* Undefined behavior. */
```

### メモリリーク

動的に借りたメモリを指す最後のポインターを失ってしまうと、そのメモリを二度と`free`できなくなります。
これを**メモリリーク**といいます。
借りたメモリを「どの関数が責任を持って解放するか」を、関数の設計段階で決めておくことが大切です。

## C99で追加された関連機能

C99では、`restrict`修飾子、可変長配列、複合リテラル、`<stdint.h>`などが追加されました。
`restrict`は、「このポインターが指すデータには、他のポインターからはアクセスしません」という約束をプログラマがコンパイラへ伝えるための機能です。
コンパイラはその約束を信じてプログラムを速くする工夫（最適化）を行いますが、もし約束を破ると未定義動作になるため、「速くなればいいな」という軽い気持ちでつけてはいけません。
